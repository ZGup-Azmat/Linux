Lesson 03（属主/属组/权限）

01 任务背景 · Mission Context

上一课你把 PRAD_project/ 的权限设好了——results/ 属组是 bioinfo、组可写。但主管一看就说：「权限位有了，人还没就位。」

原来 bioinfo 这个组根本还不存在，更别说往里面加人。主管给你三项新任务：

  • 👤 新来了两个研究员 newbie 和 colleague，给他们开账号（有家目录、能登录）。
  • 👥 建一个 bioinfo 课题组，把这两个人拉进组——这样上节课设的「组可写」才真正生效。
  • 🔒 设好密码，让每个人只能登录自己的账号。

权限是「规则」，用户和组是「执行规则的人」。这一课，你学怎么创建和管理这些人。

Context → Need → Tool

权限要分给「对的人」→ 需要创建用户、建组、把人拉进组 → 用 useradd / groupadd / usermod / passwd（都需 sudo）。

02 知识 · Knowledge（≤25%，约 15–20 分钟）

3 个概念。每个：中文 + 英文 + 心智模型 + SVG + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

概念 1 · 用户账号：whoami / id / who / getent

中文：每个能登录系统的人都有一个账号。内核其实不认名字，只认数字 UID（User ID）；用户名只是给人看的。所有用户信息存在 /etc/passwd 里。

English: Every login identity is a user account with a numeric UID; usernames are for humans. Account info lives in /etc/passwd.

语法：

whoami                # → user（当前用户名）
id                    # → uid=1000(user) gid=1000(user) groups=1000(user),27(sudo)
id -un                # 只看用户名
who                   # 谁登录了（用户名 终端 时间 IP）
w                     # 谁登录了 + 正在跑什么命令
getent passwd user    # 查 user 的完整 passwd 行

实例：id 是排查权限问题第一步——它直接告诉你「我是谁、UID 多少、在哪些组」，对应上一课权限判断里的「属主/属组」。

边界情况 · 常见失败
  • root 是 UID 0：它是唯一 UID 为 0 的超级用户，几乎不受权限限制。别把「你是自己账号」和「你是 root」混为一谈。
  • 普通用户 UID 从 1000 起：1000 以下（1–999）是系统服务账号（如 www-data、sshd），不是给人登录用的。
  • who 看的是登录会话，不是「系统里有哪些用户」。想看所有用户要用 getent passwd 或 cat /etc/passwd。
工程场景 · 为什么需要它

多用户服务器上，出了事第一件事就是问「是谁干的」。who/w 看当下谁在线，id 看某个身份有多大权限，getent 查账号是否真实存在。这三个命令是「审计」的基本功。

衔接点

本概念把 Lesson 03 的「属主/属组」落到实处——属主本质就是一个 UID。今天先会「读」用户，概念 3 再学「建/改/删」用户。

概念 2 · 组：主组 vs 附加组

中文：组（group）是「一批用户」的集合，用来批量授权。每个用户有一个主组（primary group，建号时自动指定）和零到多个附加组（supplementary groups，手动加入）。

English: A group is a set of users, used to grant permissions in bulk. Each user has one primary group and zero or more supplementary groups.

语法：

groups                # 看自己在哪些组
groups newbie         # 看 newbie 在哪些组
id -Gn                # 只列组名（不带数字）
getent group bioinfo  # 查 bioinfo 组信息（成员列表在最后）
cat /etc/group        # 所有组都在这个文件

实例：Ubuntu 上每个新用户的主组默认等于用户名（user 的主组是 user）。把研究员拉进 bioinfo 附加组后，他就能按 results/ 的「组权限」读写——这正是上一课设的 chgrp bioinfo 生效的前提。

边界情况 · 常见失败
  • usermod -G 不带 -a 会覆盖：-a 是 append（追加），少了它，原来的附加组全被清空、只剩你指定的。这是最经典的一个坑（Boss 战要埋）。
  • 加入新组后，当前已登录的会话不立刻生效，通常要重新登录（或 newgrp）才刷新组身份。
  • 主组只有一个，附加组可以有很多；id -Gn 里第一个是主组，其余是附加组。
工程场景 · 为什么需要它

团队权限永远用组来管，不逐个给个人设：6 个研究员共享一个目录，就建一个 bioinfo 组、设一次组权限，人来了 usermod -aG、人走了 gpasswd -d。这样「三个月后的人」看组名就知道权限边界。

衔接点

本概念是 Lesson 03「组权限」的另一半：03 教你「权限分给组」，本课教你「组从哪来、人怎么进组」。概念 3 把这些命令串起来。

概念 3 · 管理命令：useradd / passwd / usermod / groupadd / userdel + sudo

中文：创建、设密、改、删用户和组。这些改动影响全系统，所以都要 root 权限——用 sudo 临时提权执行。

English: Create, modify, and delete users and groups. These changes are system-wide, so they need root — via sudo.

语法：

sudo groupadd bioinfo                # 建组
sudo useradd -m -s /bin/bash newbie  # 建用户（-m 建家目录，-s 指定 shell）
sudo passwd newbie                   # 设/改密码
sudo usermod -aG bioinfo newbie      # 追加到 bioinfo 组（-a 必须！）
sudo usermod -aG sudo newbie         # 给 sudo 权限
sudo userdel -r newbie               # 删用户（-r 连家目录一起删）
sudo passwd -l newbie                # 锁账号（禁止登录，比删号更安全）

实例：给新人开一个标准账号：sudo useradd -m -s /bin/bash newbie（建号+家目录+登录 shell），再 sudo passwd newbie 设密码，最后 sudo usermod -aG bioinfo newbie 拉进课题组。

边界情况 · 常见失败
  • useradd 不带 -m 不建家目录：用户登录后可能没有家目录、shell 是 /bin/sh。给人开号务必带 -m。
  • usermod -G 忘 -a：把附加组「替换」掉，用户可能突然失去 sudo 或 bioinfo 权限。
  • userdel 不带 -r：只删账号、家目录和文件还在，离职人员的数据残留是安全隐患。
进阶提示（初学者可跳过）

adduser 是 Debian/Ubuntu 的交互式友好版（会自动建家目录、引导设密码），适合手动开几个号；但脚本里必须用 useradd（非交互、可重复）。sudo 的原理：临时以 root 身份跑单条命令，权限记在 /etc/sudoers，Ubuntu 用 sudo 组管理谁能提权。

衔接点

本概念是 Lesson 04 的落点，也是 Lesson 03 权限体系的「上游」：先有正确的用户和组，权限才有意义。下一课（Lesson 05 · Vim Boss Fight）会需要你用 sudo 编辑系统配置文件。

03 引导练习 · Guided Practice

先「读」再「改」。读的部分不需要 sudo，改的部分才要。

whoami                    # 我是谁
id                        # uid=1000(user) gid=1000(user) groups=...
groups                    # 我在哪些组
who                       # 谁登录了
getent passwd user        # 查自己那条 passwd 记录
cat /etc/group            # 系统所有组

sudo groupadd bioinfo     # 建组（开始需要 root 权限）
getent group bioinfo      # → bioinfo:x:1001:
sudo useradd -m -s /bin/bash newbie   # 建用户+家目录
sudo passwd newbie        # 设密码（交互输入两次）
sudo usermod -aG bioinfo newbie       # 拉进 bioinfo 组
groups newbie             # 验证：newbie 已在 bioinfo 组

05 排错挑战 · Debug Challenge

5 个真实 Ubuntu Server 24.04 会遇到的报错。每题 Problem → Think → Answer → Explanation。

调试 1 · useradd: Permission denied
Problem：普通用户直接跑 useradd，报 Permission denied。
💭 Think：建用户改的是全系统账号库，普通用户够格吗？
Answer：加 sudo：sudo useradd -m newbie。
🧠 Explanation：useradd 要写 /etc/passwd 等系统文件，只有 root 能改。sudo 临时提权执行这一条命令。
调试 2 · useradd: user 'newbie' already exists
Problem：建用户报 already exists。
💭 Think：名字被占了？还是只是你想再跑一遍？
Answer：getent passwd newbie 确认已存在；换名字，或先 sudo userdel -r newbie 再建。
🧠 Explanation：用户名是唯一的，重复创建会被拒绝。这是幂等性提示——脚本里建号前先判断是否已存在。
调试 3 · passwd: You may not view or modify password information for newbie
Problem：想给别人改密码，报无权查看/修改。
💭 Think：改别人的密码需要什么权限？
Answer：加 sudo：sudo passwd newbie。
🧠 Explanation：普通用户只能改自己的密码（且要验证旧密码）。改别人的密码是 root 特权。
调试 4 · 用户突然失去 sudo / bioinfo 权限
Problem：某人之前能 sudo，现在 groups 一看组没了。
💭 Think：是不是有人用 usermod -G 忘了 -a？
Answer：usermod -G（无 -a）会覆盖附加组。修复：sudo usermod -aG sudo,bioinfo 用户名。
🧠 Explanation：-a = append（追加），-G 单独用是「替换整份附加组清单」。这是最经典的权限事故。
调试 5 · newbie is not in the sudoers file. This incident will be reported.
Problem：新用户跑 sudo 报这个错。
💭 Think：新用户默认在 sudo 组里吗？
Answer：新用户默认不在 sudo 组。由管理员执行 sudo usermod -aG sudo newbie，用户重新登录后生效。
🧠 Explanation：Ubuntu 用 sudo 组控制谁能提权，只有安装时创建的第一个用户在组里。加组 + 重新登录，是标准提权流程。

06 工程场景 · Engineering Scenarios

先写下你自己的方案，再展开看参考答案。每个场景都要想「三个月后的人能否一眼看懂」。

场景 1：一个 6 人前列腺癌课题组，共享 /data/PRAD/。怎么设计用户与组，让「谁该进哪个组、谁有什么权限」在三个月后依然一目了然？

参考方案

按「角色」建组，不按人：

sudo groupadd prad            # 课题组全员
sudo groupadd prad_editors    # 有写权限的负责人
sudo usermod -aG prad 每个人
sudo usermod -aG prad_editors lead1 lead2

组名自带语义：prad = 项目名、prad_editors = 项目内可写者。人来了加组、人走了退组，权限跟着组走，不跟着人走。

场景 2：新人入职，你要一次性开好账号。写出一套「onboarding」命令（含家目录、登录 shell、课题组），并说明每步为什么这么做。

参考方案
sudo useradd -m -s /bin/bash newbie   # -m 建家目录，-s 用 bash（不是 /bin/sh）
sudo passwd newbie                    # 设初始密码，让本人第一次登录后改
sudo usermod -aG bioinfo newbie       # 拉进课题组（-a 追加，别覆盖）

可交接性：三行固定模板，注释写清每个 flag 的作用，换个人照着敲也不会漏。

场景 3：同事离职。直接 userdel -r 删号有什么风险？更稳妥的做法是什么？

参考方案

直接删号可能毁掉还没交接完的数据（-r 连家目录一起删，不可逆）。更稳妥：

sudo passwd -l 离职用户    # 先锁号，禁止登录（可逆）
# 交接完数据后，确认无遗留，再决定删号：
sudo userdel -r 离职用户    # 最后才彻底删

锁号是可逆的「冻结」，删号是不可逆的「销毁」。先冻结、后销毁，留出交接窗口。

场景 4：为什么团队权限要用「组」而不是给每个文件逐个设属主？用一句话说服你的主管。

参考方案

「权限跟着组走，人跟着组流动。」6 个人共享，就设一次组权限；人来人往，只改组的成员名单，不动任何文件。逐个设属主的话，每来一个人就要 chown 几百个文件，且三个月后没人记得谁是谁。

07 Boss 战 · Boss Fight（15–20 分钟）

任务：给共享测序中心搭一套完整的「用户 + 组 + 权限」体系，可度量、可交接，并修好一个被埋的坑。

要求（可度量交付物）：

  • 建组 bioinfo（用 getent group 留证）。
  • 开两个账号 newbie、colleague（带家目录 + bash shell）。
  • 给两人设密码，都拉进 bioinfo 组（用 groups 验证）。
  • 建共享目录 PRAD_shared/，属组 bioinfo、权限 775（组可写，衔接 Lesson 03）。
  • 用 getent + groups + ls -ld 截图整套最终状态。
⚠️ 埋了一个坑

过程中故意用 usermod -G bioinfo colleague（漏了 -a），把 colleague 的 sudo 组冲掉了。你要自己发现「colleague 的组怎么变少了」，再用 usermod -aG 修复，并把「发现 → 修复」的过程截图。

验收清单：组已建 ✅ 两账号已开 ✅ 已拉组 ✅ 共享目录 775+属组 bioinfo ✅ 埋坑已修复 ✅ 截图 + 命令进 github/lesson04/ 并 git push ✅。

真正可导入的 TSV 在 anki/lesson04-user-group.tsv，这里只做表格展示。

Commands

FrontBack
whoami当前用户名
id看 UID/GID/组
id -un只看用户名
who / w谁登录了（w 还看正在跑的命令）
groups看自己/某用户在哪些组
getent passwd user查用户完整信息
sudo useradd -m -s /bin/bash user建用户（家目录 + bash）
sudo passwd user设/改密码
sudo usermod -aG group user追加到组（-a 必加）
sudo groupadd group建组
sudo userdel -r user删用户 + 家目录
sudo passwd -l user锁账号（禁止登录）

Concepts

FrontBack
root 的 UID 是？0（唯一超级用户）
普通用户 UID 从几开始？1000（1–999 是系统账号）
主组 vs 附加组？主组唯一（新文件默认属组），附加组多个（额外授权）
usermod -aG 的 -a 作用？append 追加；不加会覆盖原附加组
useradd 不带 -m 会怎样？不建家目录，shell 默认 /bin/sh
/etc/passwd 7 字段？用户名/密码占位/UID/GID/描述/家目录/shell
为什么用组授权？权限跟组走，人跟组流动，可交接

Debugging

FrontBack
useradd 报 Permission denied缺 root，加 sudo
useradd 报 already exists用户名已存在，换名或先删
改别人密码报无权加 sudo passwd
用户突然失去 sudo/bioinfo 组usermod -G 忘了 -a，被覆盖
sudo 报 not in sudoers file新用户不在 sudo 组，usermod -aG sudo
