01 Mission Context 任务背景

测序中心每个周一早上，你都要对刚下机的一批 FASTQ 做同样的质控：

「统计每个 *.fastq 的 read 数 → 检查样本文件是否齐全 → 统计日志里的 ERROR → 生成一份报告。」

你已经连续三周，每周手敲同样的 8 条命令。今天主管说：「把这件事写成脚本，让任何同事一条命令就能跑完。」

前 13 课你学会了文件、路径、权限、grep、管道、重定向、xargs——它们都是「单个动作」。现在要把这些动作打包成一个可复用的程序。

Context（场景）→ Need（需求）→ Tool（工具）：每周重复的流程 → 需要自动化、可复用、可交接 → Bash 脚本。

02 Knowledge 核心知识（≤25%）

概念 1 · 脚本是什么 + 如何运行（What & How to Run）

定义（English）：A shell script is a plain-text file containing a sequence of shell commands, executed top-to-bottom by an interpreter (the shell).

定义（中文）：脚本就是把一条条命令按顺序写进一个文本文件，交给 shell（解释器）从上到下逐行执行。

心智模型：脚本是一份「菜谱」，bash 是照着菜谱一步步做的「厨师」。菜谱的第一行 #!/bin/bash（shebang，读作 sha-bang）告诉系统「用哪个厨师来做」。

语法：

# 第一行必须是 shebang，指定解释器
#!/bin/bash

# 以 # 开头的是注释，不会被执行
echo "Hello, sequencing center"

# 下面每一行都是一条普通命令，按顺序执行
mkdir -p qc
echo "目录已创建"

两种运行方式：

bash script.sh      # 方式一：显式交给 bash 解释，不需要执行权限

chmod +x script.sh  # 方式二：加执行权限（回顾 Lesson 03 权限）
./script.sh         #         再用 ./ 运行，读 shebang 决定解释器
边界 / 失败场景

忘加执行权限：直接 ./script.sh 报 Permission denied——文件没有 x 位。要么 chmod +x，要么改用 bash script.sh。

没写 shebang：./script.sh 时系统不知道用哪个解释器，会用当前 shell 去执行，行为可能和你预期不符（而 bash script.sh 不受 shebang 影响）。

工程场景为什么需要它：手敲命令只能你一个人复现，脚本能「写一次、跑一百次」，还能交给三个月后的同事直接运行——可复用 + 可交接，这是从「会敲命令」到「会做工程」的分水岭。

衔接：本课之前学的每条命令（find/grep/wc/管道/重定向）都是脚本的「积木」；脚本文件本身用 vim（Lesson 05）来写。

概念 2 · 变量、引用、命令替换（Variables / Quoting / Command Substitution）

定义（English）：A variable is a named box that stores a value; $(command) command substitution captures a command's output into a value; quoting controls whether the shell expands $ or treats text literally.

定义（中文）：变量是给值起名字的「盒子」；$(命令) 命令替换把命令的输出抓回来当值；引号决定 shell 要不要展开 $、还是原样照字面。

语法：

name=value              # 赋值：等号两边【不能有空格】
echo "$name"            # 取值：$ 引用
echo "${name}_suffix"   # ${} 花括号：界定变量名边界，避免和后面字符粘连

today=$(date +%F)       # 命令替换：把 date 的输出存进变量
echo "today is $today"

read -p "样本 ID: " id   # read：读用户键盘输入，存进变量
echo "你输入了 $id"

引号规则（易错）：

echo '$HOME'   # → $HOME       单引号：字面量，不展开变量
echo "$HOME"   # → /home/user  双引号：展开变量
边界 / 坑

赋值有空格：name = value 会被当成「执行命令 name，参数是 = 和 value」，报 name: command not found。

变量不引：echo $name 当 name 为空或含空格时会「词拆分」出错；稳妥习惯：永远写 "$name"。

反引号：`date` 也能做命令替换，但嵌套、可读性都差，现代写法统一用 $( )。

工程场景为什么需要它：脚本要处理「会变的东西」——目录名、样本 ID、日期、线程数——写死就失去了复用价值。变量 + 命令替换让脚本「一次写成，处处适用」。

衔接：上一课 xargs 把 stdin 转成参数；本课 $( ) 把命令输出转成「值」。它俩都做「搬运」，但 xargs 喂给命令、$( ) 喂给变量。

概念 3 · 控制流：if / for / while + 退出码（Control Flow）

定义（English）：Control flow lets a script make decisions (if) and repeat work (for/while). Every command returns an exit status ($?): 0 = success, non-zero = failure.

定义（中文）：控制流让脚本能「做判断」（if）和「重复干活」（for/while）。每条命令都有退出码（$?）：0 表示成功，非 0 表示失败。

语法：

# if：做判断（注意 [ ] 内侧两边都要有空格）
if [ -f "fastq/$id.fastq" ]; then
  echo "$id 文件存在"
else
  echo "$id 文件缺失"
fi

# for：对列表里的每一项重复做（遍历 *.fastq 常用）
for f in fastq/*.fastq; do
  echo "处理 $f"
done

# while read：逐行读文件（读样本列表常用）
while IFS= read -r line; do
  echo "$line"
done < samples.txt

常用测试条件（test / [ ]）：

条件含义
[ -f file ]文件存在且是普通文件
[ -d dir ]目录存在
[ -z "$s" ]字符串为空
[ -n "$s" ]字符串非空
[ "$a" = "$b" ]两个字符串相等

退出码 + 逻辑连接：

grep "ERROR" run1.log
echo $?          # 0 = 成功，非 0 = 失败

[ -f file ] && echo "存在" || echo "不存在"
# &&：前面成功才执行后面；||：前面失败才执行后面
边界 / 失败场景

[ ] 少了空格：[ -f "$f"] 或 ["$a" = "$b"] 都会报语法错误——[ 本身是一个命令，必须和参数用空格隔开。

测试里变量不引：[ $s = yes ] 当 s 为空时展开成 [ = yes ]，报 unary operator expected。要写 [ "$s" = yes ]。

while read 丢最后一行：如果文件最后一行没有换行符，朴素 while read 会读不到它（可加 || [ -n "$line" ] 处理）。

进阶提示（可跳过）

脚本开头加 set -euo pipefail：-e 遇到错误立即退出、-u 用了未定义变量就报错、-o pipefail 让管道任何一环失败都算失败。这是「生产级脚本」的标配，能提前挡住很多 bug。

工程场景为什么需要它：没有判断，脚本遇到「文件缺失」就崩；没有循环，就退回到手敲几百次。控制流让脚本能应对真实世界的不确定性——这正是「脚本」和「命令」的本质区别。

衔接：本课 for 循环和上一课 xargs 都能「批量处理」——xargs 擅长「把很多参数一次喂给一个命令」，for 擅长「对每一项做多步操作」。下一课 Cron 会把脚本定时自动运行，脚本是 Cron 的前提。

05 Debug Challenge 排错挑战（5 题）

每题先自己想，再展开看答案。

Debug 1 · -bash: ./script.sh: Permission denied
Problem：写了 script.sh，用 ./script.sh 运行却报 Permission denied，但用 bash script.sh 又能跑。
💭 Think：./ 运行和 bash 运行，对文件有什么不同要求？
Answer：./script.sh 需要文件有「执行权限 x」；bash script.sh 是把文件当数据喂给 bash，不需要 x。
🔧 修复：chmod +x script.sh 后再 ./script.sh（回顾 Lesson 03 权限位）。
Debug 2 · name: command not found（等号两边多了空格）
Problem：脚本里写 name = value，报 name: command not found。
💭 Think：shell 怎么理解 name = value 这一行？
Answer：shell 把它当成「运行命令 name，参数是 = 和 value」，而不是赋值。赋值必须 name=value，等号两边不能有空格。
🔧 修复：去掉空格 name=value。
Debug 3 · /bin/bash^M: bad interpreter（Windows 换行符）
Problem：在 Windows 编辑器里写好脚本传到服务器，运行报 /bin/bash^M: bad interpreter: No such file or directory。
💭 Think：那个 ^M 是什么？
Answer：Windows 换行是 \r\n，Linux 是 \n，多出来的 \r（显示为 ^M）粘在了 shebang 后面。
🔧 修复：dos2unix script.sh 转换，或用 sed -i 's/\r$//' script.sh 去掉行尾 \r。
Debug 4 · [: =: unary operator expected（测试里变量为空）
Problem：写 [ $status = OK ]，当 status 为空时报 unary operator expected。
💭 Think：status 为空时，这一行展开成什么？
Answer：展开成 [ = OK ]，= 前面没有操作数，[ 报语法错误。
🔧 修复：给变量加引号 [ "$status" = OK ]，空字符串也是一个合法操作数。
Debug 5 · while read 读文件，最后一行丢了
Problem：while read line; do …; done < samples.txt 循环比文件行数少一次，最后一行没被处理。
💭 Think：什么情况下 read 会「读到了内容却返回失败」？
Answer：当文件最后一行没有换行符时，read 读到了内容却返回非 0，循环提前结束。
🔧 修复：while IFS= read -r line || [ -n "$line" ]; do …; done —— 即使 read 返回非 0，只要 $line 非空也处理一次。

06 Engineering Scenarios 工程场景（4 题）

先写自己的方案，再看参考答案。

Scenario 1 · 把「每周一的手工流程」自动化成脚本

题目：每周一要对 fastq/ 做 read 统计 + 检查样本缺失 + 统计日志 ERROR，最后出一份报告。请把它写成一个脚本，别人一条命令就能跑。

参考答案：

#!/bin/bash
# qc_weekly.sh — 每周一质控：read 数 + 样本缺失 + ERROR 统计
set -euo pipefail

DIR="${1:-fastq}"
OUT="qc_report.txt"

[ -d "$DIR" ] || { echo "目录 $DIR 不存在" >&2; exit 1; }
: > "$OUT"

for f in "$DIR"/*.fastq; do
  [ -f "$f" ] || continue
  lines=$(wc -l < "$f")
  echo "$f: $((lines / 4)) reads" >> "$OUT"
done

while IFS= read -r id || [ -n "$id" ]; do
  [ -f "$DIR/$id.fastq" ] || echo "MISSING: $id" >> "$OUT"
done < samples.txt

echo "done: $OUT"

💡 可交接性：注释写清了「做什么」；DIR 用参数 + 默认值，换目录不用改脚本；输出统一进 qc_report.txt。

Scenario 2 · 设计「三个月后同事能接手」的脚本，要注意什么

题目：你要休假三个月，把脚本交给同事。列出至少 4 件「让同事一眼看懂」的事。

参考答案：① 开头注释写「目的 / 用法 / 输入 / 输出」；② 脚本名语义化（run_qc.sh 而不是 a.sh）；③ 用变量而不是把路径写死；④ set -euo pipefail 让出错就停，不产出半成品；⑤ 破坏性操作前加检查或提示。

Scenario 3 · for 循环 vs xargs，什么时候用哪个

题目：上一课学了 xargs，本课又学了 for。批量处理文件时，什么情况选 xargs、什么情况选 for？

参考答案：xargs 擅长「把很多参数一次喂给一个命令」（如 find … -print0 | xargs -0 rm），参数自动分批、空格安全；for 擅长「对每一项做多步操作」（如先统计、再判断、再写入），逻辑清晰可写多行。判断标准：只做一个动作 → xargs；每项要多步处理或要判断 → for。

Scenario 4 · 脚本跑到一半停了，怎么排查留下多少半成品

题目：一个脚本处理 500 个文件，跑到第 200 个时报错退出。你怎么知道「做到哪了」、怎么防止重跑时从头再来？

参考答案：① 每处理一个文件就打印进度 echo "done: $f"，出错时看最后一条就知道进度；② 结果写到独立输出文件（>> 追加），失败重跑前先看已有多少条；③ 用 set -e 让错误立即停，避免继续产出错误结果；④ 更工程化可以加「跳过已完成的」检查（[ -f "output/$id.done" ] && continue）。

07 Boss Fight 终极挑战（15–20 min）

任务：写一个生产级的 run_qc.sh，实现「一键质控报告」。要求：

  • 接收一个目录参数（默认 fastq），目录不存在要报错退出
  • 遍历目录下所有 *.fastq，统计每个的 read 数（行数 ÷ 4）
  • 结果写入 qc_report.txt（先清空再写入）
  • 开头有 set -euo pipefail 和清晰的注释（可交接）
  • 故意埋的坑：目录里混入了一个非 fastq 文件（或样本缺失），脚本要能跳过/继续，而不是崩溃

交付物（可度量）：

  1. run_qc.sh 脚本（能 ./run_qc.sh 直接运行）
  2. qc_report.txt 报告，内容 = 每个 fastq 的 read 数
  3. 一条「传错误目录 → 脚本报错退出」的验证截图
故意埋的坑

① 目录不存在要 exit 1；② 循环里混入非文件/缺失项要 continue 跳过——这两处就是本课 debug 的落点。

参考答案 / 验收清单
#!/bin/bash
# run_qc.sh — 统计目录下所有 FASTQ 的 read 数，输出报告
set -euo pipefail

DIR="${1:-fastq}"
OUT="qc_report.txt"

[ -d "$DIR" ] || { echo "错误：目录 $DIR 不存在" >&2; exit 1; }

: > "$OUT"

for f in "$DIR"/*.fastq; do
  [ -f "$f" ] || { echo "跳过（不是文件）：$f" >&2; continue; }
  lines=$(wc -l < "$f")
  reads=$((lines / 4))
  echo "$f: $reads reads" >> "$OUT"
done

echo "报告已生成：$OUT（共 $(wc -l < "$OUT") 个文件）"

✅ 验收：cat qc_report.txt 有 3 行 read 统计；./run_qc.sh not_exist 报错且 echo $? 非 0。

bash script.sh 和 ./script.sh 的区别？前者不需要执行权限，直接交给 bash；后者需要 chmod +x，按 shebang 决定解释器
