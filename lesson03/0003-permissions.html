01 任务背景 · Mission Context

上周你搭好的 RNA_Pipeline 目录被主管放上了共享服务器。昨天出事了：一位研究员手滑，rm 掉了几个病人的原始 fastq.gz——因为整个目录所有人都能写，谁都能删谁的文件。

主管给你下了三条硬要求：

  • 🥶 原始测序数据 raw_data/：所有人能读，但只有你能改——防止再被误删。
  • 👥 结果目录 results/：你和主管能写，其他人只能读。
  • ⚙️ 一个脚本 run_pipeline.sh：必须能被执行。

要完成这些，你必须搞清楚 Linux 权限体系的三个问题：谁能访问（属主/属组/其他人）、能做什么（读/写/执行）、怎么改（chmod/chown/chgrp）。

Context → Need → Tool

数据要共享、但不能被乱改 → 需要精细控制「谁能读写执行」→ 用 rwx 权限位（读）+ chmod（改）+ chown/chgrp（属主属组）。

02 知识 · Knowledge（≤25%，约 15–20 分钟）

3 个概念。每个：中文 + 英文 + 心智模型 + SVG + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

概念 1 · 权限三元组：属主 / 属组 / 其他人 × 读写执行

中文：每个文件或目录，系统把它能访问的人分成三类——属主（owner，创建者）、属组（group，同组成员）、其他人（others，除前两者外的所有人）。每一类人分别拥有三种能力：读（r，看内容）、写（w，改内容）、执行（x，运行/进入）。

English: Every file/directory has three classes of access — owner, group, others — each with read (r), write (w), execute (x) permissions.

语法（读权限）：

ls -l patient01.bam
# -rw-r--r-- 1 user bioinfo 1256000 Sep 10 09:30 patient01.bam
#  │└┬─┘└┬─┘└┬─┘  │  │       │
#  │ 属主 属组 其他  链接 属主  属组   大小    时间   名字

实例：-rw-r--r-- 表示：属主可读可写不可执行（rw-）、属组只读（r--）、其他人只读（r--）。这是 Linux 新建文件的默认权限（umask 022 的结果）。

边界情况 · 目录的 r/w/x 含义完全不同

同一组 rwx，作用在文件和作用在目录上意思不一样，这是新手最常踩的坑：

权限对文件对目录
r 读能看文件内容（cat）能列出目录里的文件名（ls）
w 写能改文件内容能新建 / 删除 / 重命名目录里的文件
x 执行能作为程序运行能进入目录（cd）、能访问里面的文件

关键：没有 x 的目录，你连 cd 都进不去，哪怕你是属主、哪怕有 r。这就是 Boss 战里要埋的坑。

工程场景 · 为什么需要它

共享服务器上几十个研究员同时干活，数据的价值远高于便利。权限就是那道闸门：测序原始数据一旦 rm 掉就永久丢失（几万元的重测序成本）。权限设计的好坏，直接决定「会不会再发生昨天那种事故」。

衔接点

本概念延续 Lesson 01 的 ls -l 第一列（当时只说「- 文件、d 目录」，今天把后面 9 位吃透）；同时为 Lesson 04「User & Group」铺垫——你今天先知道有「属主/属组」这两类人，下一课学怎么创建用户和组。

概念 2 · chmod：改权限（符号模式 + 八进制模式）

中文：chmod（change mode）修改权限。两种写法：符号模式（u/g/o/a + +/-/= + r/w/x）和八进制模式（把每组权限换算成 0–7 的一个数字）。

English: chmod changes permissions, either symbolically (u/g/o/a + +/-/= + r/w/x) or in octal (one digit 0–7 per class).

语法：

chmod u+x run_pipeline.sh      # 符号：给属主(u)加(+)执行(x)
chmod g-w patient01.bam        # 符号：去掉属组(g)的写(-w)
chmod a=r patient01.bam        # 符号：所有人(=)设为只读(r)，= 会覆盖
chmod 644 patient01.bam        # 八进制：属主 rw-，组 r--，其他 r--
chmod 755 run_pipeline.sh      # 八进制：rwxr-xr-x，脚本常用
chmod -R g+r raw_data/         # -R 递归：目录和里面所有文件一起改

符号模式角色记忆：u=user 属主、g=group 属组、o=others 其他人、a=all 所有人（默认）。运算符：+ 加权限、- 减权限、= 精确设为某权限（会覆盖原有的）。

实例：脚本刚建好时是 644（没有 x），必须 chmod +x 才能 ./run_pipeline.sh 运行。数据文件设 644 让所有人能读但只有你能写。

边界情况 · 常见失败
  • chmod -R 会把目录里每一个文件都改成同样的权限——如果你对 raw_data/ 跑了 chmod -R 777，等于把安全门全拆了。
  • 符号模式里 + 是「叠加」，= 是「覆盖」。chmod g=rwx 会把组的原有权限整个替换成 rwx，而不是「再加一点」。
  • 只有属主（或 root）能改权限。你不是属主时，chmod 会报 Operation not permitted。
进阶提示（初学者可跳过）· 特殊位 setuid / setgid / sticky

八进制第一位数字可以塞「特殊权限」：4=setuid、2=setgid、1=sticky。最实用的是 sticky bit（1）：/tmp 目录就是 1777——谁都能往里写，但只有文件属主能删自己的文件。共享数据目录设 sticky 能防止「你能写就能删别人文件」的悲剧。

衔接点

今天先掌握 u/g/o/a 与 644/755/600/700 这几种最常见组合；sticky bit 在 Boss 战里实战一次。Lesson 07（grep）里你会用 chmod +x 让检索脚本跑起来。

概念 3 · chown / chgrp：改属主与属组

中文：文件属于某个用户（属主）和某个组（属组）。chown（change owner）改属主，chgrp（change group）改属组，chown user:group 一次同时改两个。

English: A file belongs to a user and a group. chown changes the owner, chgrp changes the group, and chown user:group changes both at once.

语法：

chown user:bioinfo patient01.bam    # 属主 user，属组 bioinfo
chgrp bioinfo patient01.bam         # 只改属组为 bioinfo
chown -R user:bioinfo results/      # 递归改 results/ 下所有文件和目录
ls -l patient01.bam                 # 验证：看第 3、4 列

实例：新同事接手项目，主管把数据属主从你转给他（sudo chown newbie:bioinfo *.bam）；或者把共享目录属组设成 bioinfo，这样整个课题组的成员（都在 bioinfo 组里）就都能按「组权限」访问。

边界情况 · 常见失败
  • 普通用户不能随便 chown 别人：把文件属主改成别人（或 root）需要 sudo，否则报 Operation not permitted。这是安全设计——否则你就能把你的文件「嫁祸」给 root。
  • 改了属主，原属主立刻失去控制权：chown 后，原来的人想再改权限就得看新属主的脸色。
  • chown user file（不带冒号）只改属主、属组不变；chown :group file 只改属组、属主不变。别以为 chown user 会自动把组也改了。
工程场景 · 为什么需要它

团队协作靠的是「组」：把数据属组设成 bioinfo，组权限设成 rw，整个课题组就能协作读写，而组外的人（其他科室）只能读。这是「让三个月后接手的人一眼看懂谁该有什么权限」的基础设施。

衔接点

本概念和概念 1 的「属主/属组」是一体的：概念 1 回答「权限分给谁」，概念 3 回答「怎么换人」。Lesson 04 会正式学 useradd/groupadd，届时你会自己建 bioinfo 组、往组里加人。

03 引导练习 · Guided Practice

跟着敲。先建一个练习目录和文件，边敲边看 ls -l 的变化。

mkdir -p perm_demo && cd perm_demo
touch patient01.bam
ls -l patient01.bam            # → -rw-r--r--（默认 644）

chmod u+x patient01.bam        # 属主加执行
ls -l patient01.bam            # → -rwxr--r--（第 4 位从 - 变 x）

chmod 644 patient01.bam        # 八进制设回 rw-r--r--
chmod g+w patient01.bam        # 组加写
ls -l patient01.bam            # → -rw-rw-r--

chmod a-x patient01.bam        # 所有人去掉执行
ls -l patient01.bam            # → -rw-rw-r--（本来就没 x）

mkdir results && chmod 755 results   # 目录：属主 rwx，组/其他 r-x
ls -ld results                 # -d 看目录本身（不看里面）

05 排错挑战 · Debug Challenge

5 个真实 Ubuntu Server 24.04 会遇到的报错。每题按 Problem → Think → Answer → Explanation 展开。

调试 1 · bash: ./run_pipeline.sh: Permission denied
Problem：运行脚本 ./run_pipeline.sh，shell 报 Permission denied。
💭 Think：文件存在吗？权限里有没有 x？先别急着 sudo。
Answer：ls -l run_pipeline.sh → 看到 -rw-r--r--，缺执行位。执行 chmod +x run_pipeline.sh 再运行。
🧠 Explanation：脚本本质是「要被 shell 读取并执行」的文件，运行它需要 x 执行权限。默认新建文件是 644（无 x），所以必须手动加。用 bash run_pipeline.sh 也能跑（它绕过 x，直接让 bash 读文件），但标准做法是加 x 后 ./ 运行。
调试 2 · cat patient01.bam: Permission denied
Problem：想查看 patient01.bam，cat 报 Permission denied。
💭 Think：是文件本身没读权限，还是它所在的目录没进权限？
Answer：ls -l patient01.bam 看文件的读权限；ls -ld 看父目录的 x。文件若 600（只有属主能读）而你不是属主，就无解；若你本可读，多半是父目录缺 x。
🧠 Explanation：读一个文件要「沿途每个父目录都有 x」+「文件本身有 r」。很多人只查文件权限，忘了目录的 x 是「通行证」——没有 x，连路径都走不到文件面前。
调试 3 · cd results: Permission denied
Problem：cd results 进不去，报 Permission denied。
💭 Think：目录缺了什么？cd 需要目录的哪个权限？
Answer：ls -ld results → 若权限是 drw-r--r--（无 x），则无法进入。执行 chmod +x results。
🧠 Explanation：cd 进目录需要的是目录的 x（执行/进入）权限，不是 r。r 只负责「列出文件名」，x 才负责「走进去」。目录没了 x，等于门被焊死。
调试 4 · chmod: changing permissions of 'raw_data': Operation not permitted
Problem：想给 raw_data 改权限，chmod 报 Operation not permitted。
💭 Think：你真的是这个文件的属主吗？
Answer：ls -ld raw_data 看属主列。若不是你（比如属主是 root 或别人），你无权 chmod。找属主或 root（sudo chmod ...）。
🧠 Explanation：只有属主（或 root）能改权限。这是安全红线——否则任何用户都能把别人的文件改成自己可写。很多共享数据属主是 root 或管理员，普通研究员只能读，改不了。
调试 5 · rm: cannot remove 'SRR123_1.fastq.gz': Operation not permitted
Problem：在共享目录里删一个文件，rm 报 Operation not permitted，但目录明明所有人可写。
💭 Think：目录有 w 为什么删不掉？看看目录权限最后一位是不是 t？
Answer：ls -ld 看到 drwxrwxrwt——这是 sticky bit（1777）。只有文件属主（或 root）能删这个文件，你删的是别人的文件。
🧠 Explanation：sticky bit 让「能写目录」和「能删别人的文件」解耦。这正是 /tmp 的机制，也是共享数据目录防误删的利器。想删？先让文件属主删，或 sudo rm。

06 工程场景 · Engineering Scenarios

先写下你自己的方案，再展开看参考答案。每个场景都要想「三个月后的人能否一眼看懂」。

场景 1：6 个研究员要共用 /data/PRAD/ 目录：其中 2 个是负责人（能读写删），另外 4 个只能读不能改。课题组长要求「三个月后新来的人也能一眼看懂谁有什么权限」。你怎么设计？

参考方案

用「组」而不是逐个设人：

sudo groupadd prad_editors        # 负责人组
sudo chgrp -R prad_editors /data/PRAD
chmod -R 775 /data/PRAD           # 组内 rwx，其他人 r-x
sudo usermod -aG prad_editors lead1 lead2   # 把 2 个负责人加进组

可交接性：权限写在「组名」上，不写在人身上。新负责人来了，usermod -aG prad_editors 新同事 一行搞定，不用逐个文件 chown。组名 prad_editors 自带语义（PRAD 项目 · 编辑者）。

场景 2：你的 RNA 流程昨天还好好的，今天突然在「写结果」这一步报 Permission denied。没人改过代码。你会从哪几个方向排查权限？

参考方案

按「文件 → 目录 → 属主」三层排查：

ls -ld results/          # 1. 结果目录还有 w 吗？
ls -l results/           # 2. 里面的目标文件是什么权限/属主？
whoami                   # 3. 我是不是用错账号跑了？

最常见：昨天是 sudo 跑（文件属主变成 root），今天普通用户跑 → 写不进 root 的文件。根因是属主漂移，不是权限位被改。

场景 3：你想让一个共享目录「谁都能放文件，但谁都不能删别人的文件」。用一个数字 + 一个命令实现，并说明它和 /tmp 的关系。

参考方案

chmod 1777 shared_inbox。第一位 1 是 sticky bit，后三位 777 让所有人可读写执行。效果：谁都能往里写，但只有文件属主能删。这正是 /tmp 的默认权限。

场景 4：你离职交接，要把 pipeline/ 整棵目录树转给同事 newbie（他属于 bioinfo 组）。一条命令完成属主属组的交接，并保证他之后能正常读写。

参考方案

sudo chown -R newbie:bioinfo pipeline/。-R 递归转移整棵树，newbie:bioinfo 一次设好属主+属组。之后 ls -ld pipeline/ 确认第 3、4 列已经变成 newbie 和 bioinfo。

07 Boss 战 · Boss Fight（15–20 分钟）

任务：给一个共享测序项目 PRAD_project/ 设定一套完整、可交接的权限方案，并修好一个被埋的坑。

要求（可度量交付物）：

  • 建目录树：PRAD_project/{raw_data,trimmed,results,logs}。
  • raw_data/：设成只读（444 文件、目录加 x），防误删。

  • logs/：设 1777 sticky bit（谁都能写、谁都不能删别人的日志）。

⚠️ 埋了一个坑

有一个子目录被设成了 600（缺 x），你 cd 进去会报 Permission denied——哪怕你是属主。找到它，用 chmod 修复，并把「你如何发现并修复」的过程截图。

09 答案 · Answer Key

先独立完成再翻这里
展开全部 Lab 答案

Lab 1：touch tumor.vcf && ls -l tumor.vcf → -rw-r--r--。10 字符 = 类型(-) + 属主(rw-) + 属组(r--) + 其他(r--)。

Lab 2：chmod +x run_pipeline.sh → -rwxr-xr-x。

Lab 3：chmod 600 patient01.bam → -rw-------。

Lab 4：chmod o-r patient01.bam（从 644 出发 → -rw-r-----）。

Lab 5：touch normal.bam && chmod 644 normal.bam && ls -l normal.bam。

Lab 6：chmod -R 644 raw_data/（注意：文件 644 没问题，目录若也变 644 会丢 x，需 chmod -R u+X 或对目录单独 find -type d -exec chmod 755）。

Lab 7：chown user:bioinfo results/ 然后 ls -ld results/。

Lab 8：chmod u=rwx,g=r-x,o= file（等价 chmod 750 file）。

Lab 9：mkdir private && chmod 700 private，别人 ls private → Permission denied。

Lab 10：chmod 600 private && cd private → Permission denied（目录缺 x 无法进入）。

Lab 11：chmod 644 run_pipeline.sh → 运行报错 → chmod +x run_pipeline.sh → 成功。

Lab 12：chmod +x *.sh。

Lab 13：chgrp bioinfo shared_data && chmod 775 shared_data。

Lab 14：ls -ld 目录 看权限位 → 缺 x 则无法 cd，缺 r 则无法列出 → 对症 chmod。

Lab 15：chmod 1777 shared_tmp → ls -ld 显示 drwxrwxrwt，别人删不了你的文件。

Lab 16：chmod -R 444 raw_data + chmod -R g+w results + chmod +x *.sh，ls -lR 留证。

FrontBack
