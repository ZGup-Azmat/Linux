01 任务背景 · Mission Context

你接管了一个测序中心的共享数据盘。盘里有 12 万多个文件，散落在几千个目录里。今天主管给你三个「大海捞针」的任务：

  • 🔍 找出所有 大于 2GB 的 BAM 文件——它们快把磁盘占满了。
  • 🕐 找出 30 天没动过 的临时文件，准备清理。
  • ⚙️ 找到所有叫 run_pipeline.sh 的脚本，给它们批量加执行权限。

通配符 ls *.bam 只能在一个目录里匹配，面对「按大小、按时间、跨几千层目录」这种需求就抓瞎了。你需要 find——Linux 最强大的文件查找工具。

Context → Need → Tool

跨目录、按多条件找文件，还要对结果批量处理 → 需要递归查找 + 条件过滤 + 对结果执行动作 → 用 find（-name / -type / -size / -mtime / -exec）。

02 知识 · Knowledge（≤25%，约 15–20 分钟）

3 个概念。每个：中文 + 英文 + 心智模型 + SVG + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

概念 1 · find 基本结构：路径 + 条件 + 动作

中文：find 递归遍历指定目录树，用条件过滤出匹配的文件，再对它们执行动作。基本骨架：find 从哪找 什么条件 做什么。

English: find walks a directory tree, filters files by tests, then applies an action to matches: find where what-condition what-action.

语法：

find 路径 [条件] [动作]
find .                # 递归列出当前目录下所有文件
find . -name "*.bam"  # 按名字找 .bam（引号防止 shell 提前展开 *）
find . -name "*.bam" -ls   # 找到后用 ls 长格式显示

实例：find . -name "*.bam" 从当前目录出发，递归钻进每一个子目录，把所有 .bam 文件的完整路径打出来——这是 ls 做不到的「跨层级」查找。

边界情况 · 常见失败
  • -name "*.bam" 的引号不能省：不加引号，*.bam 会被 shell 先展开成当前目录的文件名，find 收到的就不是「模式」了。
  • -name 默认区分大小写："*.BAM" 匹配不到 .bam。想不分大小写用 -iname。
  • 在别人没权限的目录会报错：find / 遍历全盘时会刷一堆 Permission denied，加 2>/dev/null 屏蔽错误输出（后面概念 3 细讲）。
工程场景 · 为什么需要它

测序中心的文件从不会「整齐放在一个文件夹」里等你。find 是你在几万份文件里定位的唯一靠谱手段，也是所有「批量处理」的前置动作——先 find 锁定，再 exec 处理。

衔接点

本概念是 Lesson 02「路径/通配符」的升级：通配符只能在一个目录里用，find 把它扩展到「整棵目录树 + 多条件」。概念 2 展开丰富的条件。

概念 2 · 条件过滤：-type / -size / -mtime / -name

中文：find 的威力在条件：按类型（-type）、大小（-size）、修改时间（-mtime）、名字（-name），还能用 -and/-or 组合多个条件。

English: find's power is its tests: by type (-type), size (-size), modification time (-mtime), name (-name), combinable with -and/-or.

语法：

find . -type f                    # 只要文件，排除目录
find . -type d                    # 只要目录
find . -size +2G                  # 大于 2GB 的文件
find . -size 100k                 # 恰好 100KB（前后有误差，见下）
find . -mtime +30                 # 30 天前修改过的
find . -mtime -7                  # 最近 7 天改过的
find . -name "*.bam" -size +2G    # 多条件"且"：BAM 且大于 2G
find . -name "*.gz" -o -name "*.bz2"   # "或"：gz 或 bz2

实例：清理磁盘前先「盘家底」：find . -type f -size +2G 列出所有超过 2GB 的大文件，排序后决定删谁。这比盲目 du 精准得多。

边界情况 · 常见失败
  • -size 100k 不是「精确 100KB」：它匹配的是「100 个 512 字节块」上取整后的区间，实际会命中 99KB~100KB 左右的文件。要找「大于」用 +，别用等号。
  • -mtime +30 是「31 天及以上」：+n 严格大于 n，所以 +30 是 31 天起，不是「30 天」。边界容易搞错。
  • 组合条件不加括号会出错：find . -name "*.bam" -o -name "*.sam" -size +1G 中，-size 只作用于 -o 后一个条件。要明确分组得用括号转义 \( ... \)。
工程场景 · 为什么需要它

磁盘告警、数据归档、按日期批量备份……这些日常运维的起点都是「先用 find 定位」。能把「按大小+按时间+按类型」组合着写，你就具备了服务器磁盘管理的基本功。

衔接点

这些条件思路，和 Lesson 07（grep 的内容过滤）是一对：find 管「文件名/属性」，grep 管「文件内容」。概念 3 让 find 从「查找」走向「批量处理」。

概念 3 · 对结果执行动作：-exec / -delete / 2>/dev/null

中文：find 找到文件后，可以对每个匹配执行命令：-exec 命令 {} \;（{} 代表每个文件）。配合 -delete 删除、2>/dev/null 屏蔽错误，组成「查找→处理」一条龙。

English: Apply a command to each match with -exec cmd {} \; ({} = each file). With -delete and 2>/dev/null, find becomes a find-and-act pipeline.

语法：

find . -name "*.sh" -exec chmod +x {} \;    # 给每个 .sh 加执行权限
find . -type f -name "*.tmp" -delete         # 直接删除 .tmp 文件
find / -name "*.bam" 2>/dev/null             # 屏蔽无权限目录的报错
find . -size +2G -exec ls -lh {} \;          # 对每个大文件用 ls -lh 看大小

实例：主管要求「给所有脚本加执行权限」：find . -name "*.sh" -exec chmod +x {} \; 一条命令搞定，不用一个个 cd 进去改。

边界情况 · 常见失败
  • -exec rm 极危险：一旦条件写错（比如 -type d 忘了写），可能误删整个目录树。铁律：先 -print 或 -ls 看结果，确认无误再加 -exec rm 或 -delete。
  • 忘写 \; 结尾：-exec 必须用 \;（或 +）结束，否则 find 报错 find: missing argument to -exec。
  • 2>/dev/null 会把真错误也吞掉：调试时先别加，等确认无误了再加来「净化输出」。
工程场景 · 为什么需要它

「先找后动」是运维第一原则：先 -ls 看清楚要处理哪些文件，再 -exec 批量执行。这个习惯能让你避免「一个 find 删光半年的数据」这类事故。

衔接点

2>/dev/null 是「重定向」的用法，会在 Lesson 10（Redirection Boss Fight）系统讲。find + exec 是 Bash 脚本（Lesson 14）里最高频的组合之一。

05 排错挑战 · Debug Challenge

5 个真实 Ubuntu Server 24.04 会遇到的报错。每题 Problem → Think → Answer → Explanation。

调试 1 · find: missing argument to '-exec'
Problem：用了 -exec 但报 missing argument。
💭 Think：-exec 需要一个结束标记，你写了吗？
Answer：-exec 必须以 \; 或 + 结尾：find . -name "*.sh" -exec chmod +x {} \;。
🧠 Explanation：\; 告诉 find「命令到此结束」，否则 find 不知道 -exec 后的命令有多长。
调试 2 · find . -name *.bam 结果不对
Problem：-name *.bam 没加引号，结果和预期不符。
💭 Think：* 是被谁展开的？
Answer：给模式加引号：find . -name "*.bam"。
🧠 Explanation：不加引号时，shell 会先把 *.bam 展开成当前目录下的文件名，find 收到的就不是「模式」而是具体名字了。
调试 3 · find / -name "*.bam" 刷屏 Permission denied
Problem：遍历全盘时大量 Permission denied。
💭 Think：这些是正常现象还是错误？
Answer：加 2>/dev/null 屏蔽错误输出：find / -name "*.bam" 2>/dev/null。
🧠 Explanation：普通用户没有权限进入 /root、/etc 等系统目录，find 每进一个就报一次。屏蔽 stderr 只看有效结果。
调试 4 · find . -size 100k 匹配到的文件大小对不上
Problem：-size 100k 找到的文件并不是精确 100KB。
💭 Think：等号和大于的区别？
Answer：-size 100k 匹配「约 100KB 区间」（按 512 字节块取整），要「大于」用 +100k，要「小于」用 -100k。
🧠 Explanation：find 的 -size 等号是「向上取整后的近似相等」，不是精确值。精确边界判断用 +/- 更可靠。
调试 5 · find . -name "*.bam" -o -name "*.sam" -size +1G 结果出乎意料
Problem：-o 和 -size 组合，结果不符合预期。
💭 Think：-size +1G 到底作用于哪个条件？
Answer：-size +1G 默认只作用于 -o 后的最后一个条件。要明确分组用括号（转义）：find . \( -name "*.bam" -o -name "*.sam" \) -size +1G。
🧠 Explanation：-o 的优先级低于「且」，导致条件分组和你想的不一样。用 \( ... \) 显式分组才符合直觉。

06 工程场景 · Engineering Scenarios

先写下你自己的方案，再展开看参考答案。每个场景都要想「三个月后的人能否一眼看懂」。

场景 1：磁盘快满了，主管要你找出所有超过 2GB、且 30 天没人动过的大文件，列个清单准备清理。怎么写？

参考方案
find . -type f -size +2G -mtime +30 -exec ls -lh {} \;

先只 -ls/ls -lh 列清单，绝不直接删；确认后再决定是否 -delete。多条件组合 + 先看后动。

场景 2：几百个脚本散在各目录，要统一加执行权限，但你不确定「找到的是不是都是脚本」。怎么做最稳妥？

参考方案

先验证再执行：

find . -name "*.sh" -type f      # 先看清单，确认没误伤
find . -name "*.sh" -type f -exec chmod +x {} \;   # 确认后再执行

加 -type f 排除同名目录，避免给目录也加 x。

场景 3：你要写一个「每月清理临时文件」的固定命令，交给三个月后新来的同事。怎么写才能让他放心用、不会误删？

参考方案

命令要「窄、可读、先看后删」：

# 清理 30 天前的 .tmp 临时文件（先列出确认）
find /data/tmp -type f -name "*.tmp" -mtime +30 -ls
# 确认无误后，删掉上面列出的文件：
find /data/tmp -type f -name "*.tmp" -mtime +30 -delete

关键：路径写死 /data/tmp（不写 .）、条件收敛到 .tmp、注释说明用途。

场景 4：你怀疑昨天某个时间之后有文件被偷偷改过。怎么找出「最近 24 小时被修改」的文件做审计？

参考方案

find . -type f -mtime -1（近 1 天内改过）。更精确到分钟用 -mmin -1440（近 1440 分钟）。这是「谁动了我的数据」审计的基本动作。

07 Boss 战 · Boss Fight（15–20 分钟）

任务：在 tmux 里完成一次完整的「查找 → 验证 → 批量处理」磁盘管理，并修好一个被埋的坑。

要求（可度量交付物）：

  • 在 find_battle/ 里建一批测试文件（.bam / .vcf / .sh / .tmp 各若干，散在子目录）。
  • 用 find 找出所有 .sh 文件，先 -ls 列出确认。
  • 给它们批量 -exec chmod +x，用 ls -lR 验证都有 x 了。
  • 找出所有 .tmp，先列出确认，再 -delete 删除。
  • 全程在 tmux 分屏里做（左屏 find、右屏看结果），截图留证。
⚠️ 埋了一个坑

你写的清理命令里，-exec rm {} \; 忘了写 \;，find 直接报 missing argument to '-exec'。你要自己发现这个语法错误，补上 \;（或改用更安全的 -delete），并截图「报错 → 修复」的过程。

验收清单：测试文件建好 ✅ find 查找 ✅ 先看后删 ✅ 批量加权限 ✅ 埋坑已修复 ✅ 截图 + 命令进 github/lesson06/ 并 git push ✅。
