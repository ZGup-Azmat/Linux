01 任务背景 · Mission Context

最近你开始频繁 ssh 登录学校服务器干活。两个烦恼越来越明显：

  • 😤 改文件像在爬行：改一个 run_pipeline.sh 里的参数，得在终端里一点点挪光标，效率极低。
  • 💔 断线就前功尽弃：昨晚跑一个比对任务，跑到一半 Wi-Fi 抖了一下，ssh 断了，任务直接没了——它挂在你断掉的会话上。

你需要两件武器：Vim（在终端里高效改文件）和 tmux（让任务在断线后继续跑、一个屏幕开多个窗格）。而且好消息是——这俩都不需要 root 权限，你现在就能练。

Context → Need → Tool

远程改文件 + 任务要扛断线 → 需要终端编辑器 + 会话保持 → 用 vim（三模式编辑）+ tmux（session/window/pane）。

02 知识 · Knowledge（≤25%，约 15–20 分钟）

3 个概念。每个：中文 + 英文 + 心智模型 + SVG + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

概念 1 · Vim 三种模式：普通 / 插入 / 命令行

中文：Vim 是一个模式化编辑器——同一键盘按键，在不同模式里干不同的事。三核心模式：普通模式（Normal，移动/删除/复制）、插入模式（Insert，打字）、命令行模式（Command-line，保存/退出/查找替换）。

English: Vim is a modal editor — the same key does different things in each mode: Normal (move/delete/copy), Insert (type), Command-line (save/quit/search).

语法：

vim notes.txt     # 打开（进入普通模式）
i                 # 进入插入模式，开始打字
Esc               # 回到普通模式（任何时候都能按）
:                 # 进入命令行模式
:w                # 保存
:q                # 退出
:wq               # 保存并退出
:q!               # 不保存强制退出（改乱了就用它）

实例：改一个参数的标准流程：vim run_pipeline.sh → 移动光标到目标行 → i 进入插入 → 改数字 → Esc → :wq 保存退出。

边界情况 · 常见失败
  • 卡在插入模式：忘了按 Esc，一直打字，方向键还可能插入乱码。任何时候按 Esc 都能救回来。
  • :q 退出被拦：改了没保存就 :q，Vim 报 E37: No write since last change。要么 :wq 保存，要么 :q! 放弃。
  • Vim 命令区分大小写：:WQ 会报 E492（不是命令）。wq 必须小写。
工程场景 · 为什么需要它

服务器上没有图形界面，nano/vim 是仅有的编辑方式。Vim 一旦熟练，改配置、写脚本的速度远超鼠标点来点去——这是 Linux 工程师的「肌肉记忆」，也是远程运维的基本功。

衔接点

三模式是 Vim 的地基，概念 2 展开「普通模式里到底能干嘛」。后面 Lesson 14（Bash 脚本）、Lesson 21（systemd 配置）都要靠 Vim 来写和改文件。

概念 2 · Vim 编辑命令：移动 / 删除 / 复制 / 查找替换

中文：普通模式下，Vim 用键盘完成「移动、删除、复制粘贴、撤销、查找替换」。核心心法：命令 = 动作 + 范围（如 dd = 删除整行，dw = 删除一个词）。

English: In Normal mode you move, delete, copy, undo, and search/replace — a command is action + scope (e.g. dd deletes a line, dw deletes a word).

语法：

h j k l        # 左 下 上 右（替代方向键）
w / b          # 下一个词首 / 上一个词首
0 / $          # 行首 / 行尾
gg / G         # 文件开头 / 结尾
dd             # 删除当前行（剪切）
yy / p         # 复制一行 / 粘贴
u / Ctrl-r     # 撤销 / 重做
/pattern       # 向下查找，n 下一个，N 上一个
:%s/old/new/g  # 全文把 old 替换成 new

实例：把一个样本表里的 tumor 全部改成 normal：:%s/tumor/normal/g 回车，一键全文替换，不用一个个手改。

边界情况 · 常见失败
  • 替换漏了 /g：:%s/tumor/normal 只替换每行第一个匹配；加 g（global）才替换整行所有。
  • dd 其实是「剪切」不是「删除」：删掉的行在寄存器里，p 还能贴回来——误删了先别慌，p 或 u 都能救。
  • 终端方向键乱码：某些环境在 Vim 里按方向键会插入 A B C D，是因为进入了插入模式；用 hjkl 更稳。
工程场景 · 为什么需要它

生信里天天改 VCF/GTF/配置表：找某个基因、批量替换样本名、删掉几行注释。用鼠标在 3000 行文件里翻，又慢又容易漏；用 / 查找 + :%s 替换，几秒搞定且可复现。

衔接点

本概念的「查找替换」思路，和 Lesson 07（grep）的检索是同一套；等你写 Bash 脚本时，这些编辑命令就是改脚本的日常。

概念 3 · tmux：会话 / 窗口 / 窗格

中文：tmux 是「终端复用器」——一个终端里开多个窗口、一个窗口切多个窗格，更关键的是：会话可以脱离（detach）后再接回（attach），断线/关电脑任务都不停。

English: tmux multiplexes one terminal into many windows and panes; crucially, a session can be detached and reattached — tasks survive disconnects.

语法：

tmux                  # 新建会话
tmux new -s rna       # 新建并命名（推荐，好认）
tmux ls               # 列出所有会话
tmux attach -t rna    # 重新接回会话

# 会话内（先按 Ctrl-b 前缀，再按后面的键）
Ctrl-b d              # detach 脱离（任务继续跑）
Ctrl-b %              # 左右分屏
Ctrl-b "              # 上下分屏
Ctrl-b 方向键          # 切换窗格
Ctrl-b x              # 关闭当前窗格
Ctrl-b c              # 新建窗口
exit                  # 退出当前窗格/会话

实例：跑比对任务前：tmux new -s align → 启动命令 → Ctrl-b d 脱离 → 关电脑走人。明天回来 tmux attach -t align，任务还在跑、结果还在。

边界情况 · 常见失败
  • 前缀键记错：tmux 的命令都要先按 Ctrl-b（不是 Ctrl-c，那个是打断）。很多人狂按 Ctrl-c 结果把任务杀了。
  • attach 报 no sessions：没有正在运行的会话却想 attach；先 tmux ls 看有没有。
  • 忘了自己在 tmux 里：分屏后屏幕底部有状态条提示；exit 能退出当前窗格。
工程场景 · 为什么需要它

生信任务动辄跑几小时到几天，远程 ssh 一断就全废。tmux 让任务「长在服务器上、不挂在你的连接上」；分屏则让你一边看日志、一边敲命令，不用开八个终端窗口。

衔接点

tmux 是远程工作的标配，后面 Lesson 17（进程）、Lesson 36–37（HPC/SLURM）都会在 tmux 里跑长任务。本课之后，你的「服务器日常」就成型了。

03 引导练习 · Guided Practice

先 Vim 再 tmux，跟着敲。

echo "tumor tumor" > demo.txt
vim demo.txt          # 打开，进入普通模式
# 按 i 进入插入模式，打几个字
# 按 Esc 回普通模式
:wq                   # 保存退出

vim demo.txt          # 再打开
:%s/tumor/normal/g    # 全文替换 tumor → normal
:wq                   # 保存退出
cat demo.txt          # 验证：normal normal

tmux new -s test      # 新建命名会话
# 里面跑：Ctrl-b % 左右分屏
# Ctrl-b d 脱离
tmux ls               # 看到 test 会话还在
tmux attach -t test   # 接回
exit                  # 退出会话

05 排错挑战 · Debug Challenge

5 个真实 Ubuntu Server 24.04 会遇到的报错。每题 Problem → Think → Answer → Explanation。

调试 1 · E37: No write since last change (add ! to override)
Problem：改了文件后直接 :q，Vim 报 E37 不让退。
💭 Think：你是想保存还是不保存？
Answer：想保存就 :wq；想放弃就 :q!（感叹号 = 强制）。
🧠 Explanation：Vim 防止你「改了却忘了存」就退出。! 在 Vim 里是「强制执行/放弃安全检查」的通用后缀。
调试 2 · E492: Not an editor command: WQ
Problem：输入 :WQ 报 E492。
💭 Think：Vim 命令区分大小写吗？
Answer：:WQ 应写成小写 :wq。
🧠 Explanation：Vim 命令严格区分大小写，wq 和 WQ 是两个不同的东西。:WQ 不存在，所以 E492。
调试 3 · 在 vim 里方向键打出 A B C D 乱码
Problem：插入模式下按方向键，屏幕冒出 A、B、C、D 字母。
💭 Think：是不是终端把方向键当成了转义序列？
Answer：先 Esc 回普通模式，改用 hjkl 移动。
🧠 Explanation：某些老旧终端里，方向键在 Vim 的插入模式会变成转义序列（^[[A 等），显示成 A/B/C/D。hjkl 是 Vim 的「原生方向键」，永远可靠。
调试 4 · tmux attach → no sessions
Problem：tmux attach 报 no sessions。
💭 Think：真的没有会话，还是名字记错了？
Answer：先 tmux ls 列出会话；若有，用 tmux attach -t 会话名 指定。
🧠 Explanation：tmux attach 默认接「最近一个」；没有任何会话（服务器重启过、或从没建过）时就会报 no sessions。
调试 5 · E212: Can't open file for writing
Problem：vim 里 :w 保存报 E212。
💭 Think：文件/目录的写权限？还是路径不存在？
Answer：:pwd 看当前目录，ls -l 看权限；无权限则换个能写的目录，或（有 root 时）sudo。
🧠 Explanation：E212 通常是「目标文件/目录没有写权限」（衔接 Lesson 03）。普通用户只能写自己家目录和 /tmp，写系统目录会撞这个错。

06 工程场景 · Engineering Scenarios

先写下你自己的方案，再展开看参考答案。每个场景都要想「三个月后的人能否一眼看懂」。

场景 1：你要 ssh 到服务器跑一个 6 小时的 RNA 比对，但宿舍 Wi-Fi 不稳、可能断线。怎么保证断线了任务不丢？

参考方案
tmux new -s align_PRAD      # 命名会话，一看就知道是 PRAD 的比对
# 启动比对命令……
# Ctrl-b d 脱离，关电脑走人
# 回来：
tmux attach -t align_PRAD   # 接回，任务还在跑

核心：任务跑在 tmux 会话里，不挂在你 ssh 连接上。断线只断 ssh，不断 tmux 会话。

场景 2：一个 3000 行的样本清单，要把里面所有 SRR12345678 改成 SRR99999999。用鼠标一个个改？还是？

参考方案

vim 清单 → :%s/SRR12345678/SRR99999999/g 回车，一条命令全文替换。/g 保证每行所有匹配都换，不是只换第一个。

场景 3：你想一边看实时日志、一边敲命令调试，但不想开四个终端窗口。怎么做？

参考方案

tmux 分屏：tmux new -s debug → Ctrl-b % 左右分屏 → 左窗跑命令、右窗 tail -f 日志。需要更多窗格就继续 Ctrl-b % / Ctrl-b "，用 Ctrl-b 方向键 切换。

场景 4：你和同事共用服务器，各自跑任务。三个月后新来的同事看 tmux ls 怎么快速搞清「谁在跑什么」？

参考方案

靠命名约定：会话名 = 「任务类型_项目名」，如 qc_RNA（RNA 质控）、align_PRAD（PRAD 比对）、call_WES（外显子变异检测）。名字自带语义，看一眼 tmux ls 就懂，不用逐个 attach 进去查。

07 Boss 战 · Boss Fight（15–20 分钟）

任务：用 vim 修好一个脚本，再用 tmux 分屏「边改边看日志」，并修好一个被埋的坑。综合运用 Lesson 01–04 的技能。

要求（可度量交付物）：

  • 在 PRAD_pipeline/ 目录里（复习 Lesson 01 建目录），有个脚本 run_pipeline.sh。
  • 用 vim 把脚本里所有的 tumor 替换成 normal（复习 Lesson 02 路径 + 本课替换）。
  • 用 tmux 开一个命名会话 debug_PRAD，分屏：左窗编辑脚本、右窗 tail -f results.log（复习 Lesson 02 路径）。
  • 给脚本加执行权限（复习 Lesson 03：chmod +x，不需要 sudo）。
  • Ctrl-b d 脱离，再 tmux attach 接回，截图证明会话没丢。
⚠️ 埋了一个坑

脚本里有一行被你 vim 替换时漏了 /g，导致某行只替换了第一个 tumor、行尾还有一个没换。你要自己发现「怎么没替换干净」，重跑 :%s/tumor/normal/g 修好，并截图「发现 → 修复」的过程。

验收清单：目录/脚本 ✅ vim 替换干净 ✅ tmux 分屏+脱离+接回 ✅ 脚本可执行 ✅ 埋坑已修复 ✅ 截图 + 命令进 github/lesson05/ 并 git push ✅。
