01 Mission Context 任务背景

测序中心刚下机一批原始数据：一个 SRR12345678.fastq 就 5 GB，磁盘眼看要满。主管让你：

  • 🗜️ 把这批 .fastq 压缩起来，省出空间（FASTQ 是纯文本，gzip 能压掉 60–75%）。
  • 📦 把一个项目的 raw_data/ + results/ 打包成一个文件，发给合作者。
  • 🔍 不解压就能看一眼 5 GB 文件的开头，确认数据没坏。

压缩的核心区别：gzip 管单个文件，tar 管打包多个文件/目录，两者合体就是测序行业最常用的 .tar.gz。

Context → Need → Tool

磁盘满/要传输一堆文件 → 需要压缩 + 打包 → gzip（单文件）/ tar -czf（多文件+压缩）/ zcat（不解压查看）。

02 Knowledge 知识（≤25%，约 15–20 分钟）

3 concepts. Each: 英文定义 + 中文注释 + 心智模型 + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

Concept 1 · gzip / gunzip: compress & decompress a single file

English: gzip compresses a single file into a .gz file and, by default, removes the original. gunzip (or gzip -d) reverses it.

中文：gzip 把单个文件压缩成 .gz（默认删除原文件），gunzip（或 gzip -d）解压还原。

Syntax：

gzip sample.fastq             # → sample.fastq.gz，原文件被删除
gunzip sample.fastq.gz        # → 还原 sample.fastq，.gz 被删除
gzip -d sample.fastq.gz       # -d: decompress，等价 gunzip
gzip -k sample.fastq          # -k: keep 保留原文件（不删）
gzip -c sample.fastq > sample.fastq.gz   # -c 输出到 stdout，也保留原文件
zcat sample.fastq.gz | head -n 4   # 不解压，直接看前 4 行
zgrep "ERROR" sample.log.gz        # 不解压，直接搜内容
zless sample.fastq.gz              # 不解压，翻页浏览

实例：5 GB 的 sample.fastq 跑 gzip 后变成约 1.5 GB 的 sample.fastq.gz，磁盘立刻省出 3.5 GB。想确认压缩没坏、数据头还在，用 zcat sample.fastq.gz | head -n 4 直接看前 4 行，不用先解压整个文件。

边界情况 / 常见失败
  • gzip 默认删除原文件：没有 -k 或 -c 时，gzip file 会删掉原文件只留 .gz。想保留用 -k。
  • gzip 只能压单个文件：不能直接压一个目录（gzip project/ 会报错）。打包多个文件/目录是 tar 的事（概念 2）。
  • 已压缩的格式再压几乎不缩：.bam、.jpg、.png、.gz 本身已压缩，再 gzip 只会浪费 CPU、大小几乎不变。
  • zcat/zgrep 只认 gzip 格式：对普通文件或 .tar 用 zcat 会报 not in gzip format。
工程场景 / 为什么需要它

.fastq.gz 是测序行业的通用格式——NCBI、ENA、GEO 上传的原始数据几乎都是它。学会 gzip + zcat，等于拿到「和全世界交换测序数据」的入场券。

衔接点

zgrep 就是 Lesson 07 grep 的「压缩版」，直接对 .gz 搜内容。概念 2 解决 gzip 管不了的「多文件/目录」打包问题。

Concept 2 · tar: bundle + compress（.tar.gz）

English: tar (tape archive) bundles many files/directories into one .tar file — that only packs, it does not compress. Adding -z compresses the bundle with gzip, producing the standard .tar.gz ("tarball").

中文：tar 把多个文件/目录打包成一个 .tar（只打包不压缩），加 -z 用 gzip 压缩成 .tar.gz（俗称 tarball）。

Syntax：

tar -czf project.tar.gz project/    # c=create z=gzip f=file：打包并压缩
tar -tzf project.tar.gz             # t=list：只列内容，不解压
tar -xzf project.tar.gz             # x=extract：解压还原
tar -czvf project.tar.gz project/   # v=verbose：显示过程
tar -cjf archive.tar.bz2 dir/       # j=bzip2 压缩（概念 3）
tar -cJf archive.tar.xz  dir/       # J=xz 压缩（概念 3）

实例：把一整个项目（raw_data/ + results/ + logs/）打包发合作者：tar -czf project_2026-10-03.tar.gz project/ 一个命令产出一个文件，对方 tar -xzf 就能还原整个目录结构。

边界情况 / 常见失败
  • 忘记 -f：tar -cz archive dir 没写文件名，会报 Refusing to read archive contents from terminal (missing -f option?)。-f 后面必须紧跟归档文件名。
  • 创建时忘了 -z：tar -cf x.tar.gz dir/ 生成的是未压缩的 .tar（只是文件名带 .gz 而已）。解压时强制 -z 会报 not in gzip format。
  • 对单个 .gz（非 .tar.gz）用 tar：tar -xf sample.fastq.gz 会报 This does not look like a tar archive——gzip 文件和 tar 包是两回事。
  • 解压会覆盖同名文件：解压到当前目录会直接覆盖已有同名文件，解压前先 tar -tzf 看清里面有什么。
进阶提示（可跳过）

现代 GNU tar 读（-x / -t）时会自动识别 gzip/bzip2/xz，所以 tar -xf x.tar.gz 不加 -z 也能解。但创建时（-c）必须显式加 -z 才会压缩。规范做法：读也写清楚 -z，意图更明白、跨系统更稳。

衔接点

概念 1 是「单文件压缩」，tar 是「多文件打包 + 压缩」的组合拳。概念 3 讲压缩工具怎么选。

Concept 3 · Choosing the tool: gzip / bzip2 / xz / zip + what NOT to compress

English: Different compressors trade ratio against speed — gzip is fastest with decent ratio, bzip2 compresses better, xz best but slowest; zip is for cross-platform (Windows) exchange.

中文：不同工具在「压缩率 vs 速度」间取舍：gzip 最快、bzip2 更小、xz 最小但最慢；zip 用于跨平台（Windows）交换。

Syntax：

bzip2 file        # → file.bz2
bunzip2 file.bz2  # 解压
xz file           # → file.xz（压缩率最高，最慢）
unxz file.xz      # 解压
zip archive.zip f1 f2   # 打包成 .zip（跨平台）
unzip archive.zip       # 解压

实例：FASTQ 用 gzip（快、所有生信工具都认 .fastq.gz）；需要长期归档、追求最小的基因组大索引用 xz；要和用 Windows 的同事交换用 zip。

边界情况 / 常见失败
  • zip/unzip 可能没预装：Ubuntu Server 24.04 最小安装不含 zip/unzip，要 sudo apt install zip unzip（当前无 root，跳过，租服务器后补）。
  • 已压缩的格式再压是浪费：.bam（BGZF 压缩）、.jpg、.png、.zip、.gz 本身已压缩，再 gzip 只会烧 CPU、几乎不缩。
  • xz 解压慢、占内存高：解一个大的 .xz 比 gzip 慢很多，大文件解压要有耐心、别以为卡死了。
工程场景 / 为什么需要它

选错工具不是大错，但「给 Windows 同事发 .tar.gz、给已压缩的 .bam 再套一层 gzip」是典型新手错误。记住一句：数据要交换看格式，省空间看是否已压缩。

衔接点

Part II（Shell 工程）会在管道里大量用 zcat file.gz | grep ...、用 tar.gz 做备份和传输。这是 Part I 的收官。

03 Guided Practice 引导练习

Follow along. 不需要 sudo，建议在 tmux 里做。

tmux new -s complab                       # tmux 习惯
mkdir -p complab && cd complab
# 造一个 4 行的 FASTQ 风格文件
printf '@SRR0000001.1\nACGTACGTACGT\n+\nIIIIIIIIIIII\n' > sample.fastq
ls -lh sample.fastq                        # 看原文件大小

gzip sample.fastq                          # 压缩 → sample.fastq.gz（原文件消失）
ls -lh sample.fastq.gz                     # 看压缩后
zcat sample.fastq.gz | head -n 4           # 不解压看前 4 行
gunzip sample.fastq.gz                     # 解压还原

# tar 打包一个目录
mkdir -p project/raw project/results
printf '@SRR0000002.1\nGATTACAGATT\n+\nIIIIIIIIII\n' > project/raw/read1.fastq
printf 'gene\tcount\nTP53\t120\n' > project/results/counts.txt
tar -czf project.tar.gz project/           # 打包 + 压缩
tar -tzf project.tar.gz                    # 只列内容，不解压
mkdir extract && tar -xzf project.tar.gz -C extract   # 解压到 extract/
find extract -type f                       # 验证目录结构还原

05 Debug Challenge 排错挑战

5 个真实 Ubuntu Server 24.04 会遇到的报错。Problem → Think → Answer → Explanation。

调试 1 · tar -xz data.tar.gz 报 Refusing to read archive contents from terminal
Problem：想解压，结果 tar 拒绝读。
💭 Think：-f（文件名）是不是漏了？
Answer：-f 后面必须跟归档文件名：tar -xzf data.tar.gz。
🧠 Explanation：没 -f 时 tar 从标准输入（终端）读归档，于是拒绝。记住 -f 永远紧跟文件名。
调试 2 · tar -xf sample.fastq.gz 报 This does not look like a tar archive
Problem：对一个 gzip 文件用 tar 解压。
💭 Think：.gz 和 .tar.gz 一样吗？
Answer：sample.fastq.gz 只是「gzip 压缩的单个文件」，不是 tar 包。要看内容用 zcat，不是 tar。
🧠 Explanation：gzip 管单文件，tar 管打包。tar 解压 gzip 单文件后看到的不是 tar 格式，所以报错。
调试 3 · gzip sample.fastq.gz 报 already has .gz suffix -- unchanged
Problem：对已压缩文件再 gzip。
💭 Think：它是不是已经压过了？
Answer：文件已经是 .gz，gzip 拒绝二次压缩。先 gunzip 还原，或干脆别压。
🧠 Explanation：gzip 检测到 .gz 后缀会跳过，防止把 file.gz 变成 file.gz.gz。
调试 4 · gunzip sample.fastq.gz 报 already exists; not overwriting
Problem：解压时同名文件已存在。
💭 Think：当前目录是不是已经有个 sample.fastq？
Answer：gzip 默认不覆盖。先删旧的，或用 gunzip -f sample.fastq.gz 强制覆盖。
🧠 Explanation：为避免误覆盖数据，gzip 默认拒绝。确认旧的不要了再 -f。
调试 5 · zcat data.tar 报 not in gzip format
Problem：对一个未压缩的 tar 用 zcat。
💭 Think：data.tar 是不是没压过？
Answer：zcat 只认 gzip。未压缩的 tar 用 tar -tf data.tar 查看。
🧠 Explanation：zcat = gzip -dc，碰到非 gzip 数据就报 not in gzip format。

06 Engineering Scenarios 工程场景

先写自己的方案，再展开看答案。每个场景想「三个月后的人能否看懂」。

场景 1：500 个 .fastq 把磁盘占满了。你想省空间，但后续生信工具（如 fastqc）还需要能直接读这些文件。怎么压缩最合适？

参考方案

gzip -k *.fastq（或逐个 gzip）——把每个 FASTQ 压成 .fastq.gz，工具都能直接读 .gz，且省 60–75% 空间。不要 tar 成一个大包，因为 tar 包不能让工具按文件读取。

场景 2：要把整个项目（raw_data/ + results/ + scripts/）发给合作者。怎么打包让对方三个月后也能立刻看懂？

参考方案

tar -czf project_$(date +%F).tar.gz raw_data/ results/ scripts/——文件名带日期、含多个目录、-z 压缩，一个文件发走。对方 tar -xzf 就还原整个结构。

场景 3：一个 5 GB 的 .fastq.gz，你只想确认前 4 行数据头（read ID 和序列）没坏，不想解压整个文件。怎么做？

参考方案

zcat sample.fastq.gz | head -n 4——流式只读前 4 行就停，不落盘、不占额外空间、秒回。

场景 4：你要归档 alignment.bam（已压缩）和 counts.txt（纯文本）两个文件。压缩策略该怎么定？

参考方案

.bam 已 BGZF 压缩，别再 gzip（纯浪费 CPU）；只压纯文本：gzip counts.txt。若要一起打包，tar -czf archive.tar.gz alignment.bam counts.txt.gz——tar 的 gzip 层对 bam 收益也有限，但打包方便传输。

07 Boss Fight（15–20 分钟）

任务：建一个迷你测序项目，正确压缩 + 打包 + 验证，并修好一个被埋的坑。

要求（可度量交付物）：

  • 建 comp_battle/，造 raw_data/（2 个 .fastq）和 results/（1 个 counts.txt）。
  • 把每个 .fastq 用 gzip -k 压缩（保留原文件，模拟「工具还能读原文件」）。
  • 用 tar -czf comp_battle_$(date +%F).tar.gz raw_data/ results/ 打包整个项目。
  • 用 tar -tzf 列出归档内容，确认两个目录都在。
  • 用 zcat ... | head -n 4 确认某个 .fastq.gz 数据完好。
  • 全程 tmux 分屏（左屏执行、右屏验证），截图留证。
⚠️ 埋了一个坑

你打包时手滑写成了 tar -cf comp_battle.tar.gz raw_data/ results/（漏了 -z，只打包不压缩）。当你用 tar -xzf comp_battle.tar.gz 解压验证时，报错 gzip: stdin: not in gzip format。你要自己发现「创建时漏了 -z，文件名叫 .tar.gz 但其实是未压缩的 .tar」，删掉重来 tar -czf ...，再 tar -tzf 验证成功，截图「报错 → 修复」。

验收清单：项目目录树 ✅ FASTQ 已 gzip ✅ 归档已打包 ✅ 内容已验证 ✅ 埋坑（漏 -z）已修复 ✅ 截图 + 命令进 github/lesson08/ 并 git push ✅。

gunzip 报 already exists not overwriting同名文件存在，删旧或 -f 覆盖
zcat x.tar 报 not in gzip formatx.tar 未压缩，用 tar -tf 查看
