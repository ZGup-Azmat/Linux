01 Mission Context 任务背景

昨天你学会了压缩（Lesson 08）。今天主管要你「不建中间文件」就完成一堆统计：

  • 🧬 一个 5 GB 的 SRR12345678.fastq.gz，想知道里面有几条 read（不解压、不落盘）。
  • 📊 一个 sample.vcf 变异文件，想知道有多少条变异记录（跳过 # 开头的注释头）。
  • 🏆 一个基因表达表，想找「表达量最高的 top 10 基因」。
  • 🔍 一堆日志，想捞 ERROR 并数有多少行。

答案全在管道 | 里。它让命令像流水线一样接起来：一个命令的输出，直接流进下一个命令的输入，中间结果不落盘、不占空间、一气呵成。

Context → Need → Tool

要对数据做多步处理又不想建中间文件 → 需要把命令串起来 → |（管道）+ 过滤器 grep/sort/uniq/wc/head/tail。

02 Knowledge 知识（≤25%，约 15–20 分钟）

3 concepts. Each: 英文定义 + 中文注释 + 心智模型 + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

Concept 1 · The pipe |: stdout → stdin

English: The pipe | takes the standard output (stdout) of the left command and feeds it as standard input (stdin) to the right command. Data flows left → right.

中文：管道 | 把左边命令的标准输出（stdout）喂给右边命令的标准输入（stdin），数据从左流向右。

Syntax：

cmd1 | cmd2 | cmd3              # 可无限串联，数据从左到右流
ls -l | grep "\.fastq$"         # ls 的输出喂给 grep 过滤
cat align.log | grep ERROR | wc -l   # 三段：读 → 滤 → 数

实例：ls -l | grep "\.fastq$"——ls -l 列出所有文件的详细行，管道把这一整块文本喂给 grep，grep 只留下以 .fastq 结尾的行。不用先把 ls 结果存成文件再搜。

边界情况 / 常见失败
  • 管道只传 stdout，不传 stderr：命令的报错（stderr）会绕过管道直接打到屏幕，不会被下游处理。
  • 右边命令必须读 stdin：grep ERROR align.log | ls 里 ls 不读 stdin，管道喂的东西被无视，只会看到 ls 自己列目录。
  • 管道里每个命令跑在自己的子进程里：里面 cd 或改的变量不会传回你的 shell（如 echo hi | read x 之后 $x 是空的）。
工程场景 / 为什么需要它

生信里「读文件 → 过滤 → 统计 → 排序」是每天的固定动作。管道让你把这些步骤写成一条命令，中间不落盘——5 GB 的文件不用先解压存一份再处理。

衔接点

管道的两个「接头」你已经会了：左边常用 cat/zcat（Lesson 08），右边常用 grep（Lesson 07）。概念 2 把右边换成一组「过滤器」。

Concept 2 · Pipeline filters: grep / head / tail / wc / sort / uniq

English: A pipeline chains several filter commands, each reading stdin and writing stdout, so data flows through them in stages — filter, count, sort, deduplicate, trim.

中文：管道把多个「过滤器」串起来，每个都读 stdin、写 stdout，数据逐级流过——过滤、统计、排序、去重、截断。

Syntax：

zcat sample.fastq.gz | wc -l             # 数总行数（read 数 = 行数/4）
zcat sample.fastq.gz | grep "^@" | wc -l  # 数 read 数（@ 开头是 header）
grep -v "^#" sample.vcf | wc -l           # 数变异记录（跳过 # 头）
grep -c "^>" genome.fa                   # 数 FASTA 序列条数
cut -f1 counts.tsv | sort | uniq -c | sort -nr | head -n 10   # 表达量 top10

实例：「表达量最高的 top 10 基因」：cut -f1 取第一列基因名 → sort 排序（让相同的相邻）→ uniq -c 计数 → sort -nr 按次数降序 → head -n 10 取前 10。五段一条命令，几毫秒出结果。

边界情况 / 常见失败
  • uniq 只去「相邻」重复：a a b a 不去重成 a b a。要先 sort 让相同项相邻。
  • sort 要等全部输入读完才输出：大文件排序会先缓冲，看起来像卡住，属正常。
  • head 提前退出会让上游收到「broken pipe」：如 yes | head -n 3，无害但会在 stderr 报一句。
  • wc -l 数的是「行」：FASTQ 每 read 4 行，别把行数当 read 数。
工程场景 / 为什么需要它

「这个 VCF 有多少变异」「这个 FASTA 有多少序列」「哪个基因最热」——这些就是生信日常工作，一条管道搞定。养成「能管道就不写中间文件」的习惯。

衔接点

这些过滤器只是开胃菜，Lesson 11/12 的 awk、sed 是更强大的过滤器。概念 3 解决「结果想存下来」的问题。

Concept 3 · Pipe vs redirection + tee

English: | sends stdout to another command; > / >> write stdout to a file. tee writes to a file and passes the data onward down the pipe.

中文：| 把 stdout 送给下一个命令，>/>> 把 stdout 写进文件；tee 既写文件又继续把数据传下去。

Syntax：

grep ERROR align.log > errors.txt          # 写进文件（覆盖）
grep ERROR align.log >> errors.txt         # 追加到文件
grep ERROR align.log | tee errors.txt | wc -l  # 存文件 + 继续数行
grep ERROR align.log | tee -a errors.txt | wc -l  # -a 追加

实例：排查日志时想「边存边看」：grep ERROR align.log | tee errors.txt | wc -l——先把 ERROR 行存进 errors.txt 留档，同时把行数传给 wc -l 打出来。一份数据两条路。

边界情况 / 常见失败
  • > 会静默覆盖：文件已存在时 > 直接清空重写，不提示。重要文件先备份，或用 >> 追加。
  • tee 默认也是覆盖：追加用 tee -a。
  • > 只重定向 stdout：报错（stderr）不会进文件，要 2>（Lesson 10 细讲）。
  • | 和 > 别混：grep x file | result.txt 是错的，| 后面只能接命令，接文件名要用 >。
工程场景 / 为什么需要它

「处理结果既要留档、又要继续往下算」是常态。tee 让你在管道中间「打个岔」存一份检查点，而不打断整条流水线。

衔接点

这是 Lesson 10（Redirection Boss 战）的引子——下节课专门把 >/>>/2>/< 这些重定向彻底吃透。

03 Guided Practice 引导练习

Follow along. 不需要 sudo，建议在 tmux 里做。

tmux new -s pipelab                      # tmux 习惯
mkdir -p pipelab && cd pipelab

# 造一个 8 行（2 条 read）的 FASTQ
printf '@SRR0000001.1\nACGTACGT\n+\nIIIIIIII\n@SRR0000002.1\nTGCATGCA\n+\nIIIIIIII\n' > reads.fastq

cat reads.fastq | wc -l                   # 8 行
cat reads.fastq | grep "^@"               # 2 个 @ 开头的 header 行
cat reads.fastq | grep "^@" | wc -l       # 2 = read 数
cat reads.fastq | head -n 4               # 第一条 read

# sort | uniq 统计基因出现次数
printf 'TP53\nEGFR\nTP53\nBRCA1\nEGFR\nEGFR\n' > genes.txt
cat genes.txt | sort | uniq -c            # 每个基因出现几次
cat genes.txt | sort | uniq -c | sort -nr | head -n 2   # 最热的 top 2

# tee 边存边数
cat reads.fastq | grep "^@" | tee headers.txt | wc -l   # 存 headers.txt + 数 2
cat headers.txt                          # 确认存下来了

05 Debug Challenge 排错挑战

5 个真实 Ubuntu Server 24.04 会遇到的报错。Problem → Think → Answer → Explanation。

调试 1 · grep "SRR" reads.fastq | ls 结果不对，只剩目录列表
Problem：想看 grep 结果，却只看到 ls 列目录。
💭 Think：ls 会读 stdin 吗？
Answer：ls 不读 stdin，管道喂给它的东西被无视。改成能读 stdin 的命令，如 grep "SRR" reads.fastq | wc -l。
🧠 Explanation：管道只对「读 stdin 的命令」有意义。ls/cd/rm 这类不读 stdin 的命令接在管道右边是浪费。
调试 2 · cat genes.txt | uniq -c 计数不对（TP53 出现两次却没合并）
Problem：uniq 没把重复的合并干净。
💭 Think：uniq 去的是「相邻」还是「全部」重复？
Answer：uniq 只去相邻重复。先 sort：cat genes.txt | sort | uniq -c。
🧠 Explanation：sort 把相同项排到一起，uniq 才能正确去重。这是管道最常见的坑。
调试 3 · grep -r "error" . | wc -l 屏幕还是冒出 Permission denied
Problem：管道该「接住」报错，但报错还是打到屏幕。
💭 Think：管道传的是哪个流？
Answer：管道只传 stdout，Permission denied 是 stderr，绕过管道。要静音加 2>/dev/null。
🧠 Explanation：stdout 走管道、stderr 直接上屏。Lesson 10 会专门讲 stderr 重定向。
调试 4 · cat reads.fastq | wc -l 得到 8，但你以为是 2 条 read
Problem：行数和 read 数对不上。
💭 Think：一条 read 占几行？
Answer：FASTQ 每 read 4 行，8 行 = 2 条 read。直接数 read 用 grep -c "^@" reads.fastq。
🧠 Explanation：wc -l 数行不数记录。记住 FASTQ 的 4 行结构（@header / seq / + / quality）。
调试 5 · grep ERROR align.log > errors.txt 把昨天的 errors.txt 覆盖没了
Problem：旧的 errors.txt 被静默清空重写。
💭 Think：> 是覆盖还是追加？
Answer：> 覆盖、>> 追加。想保留旧内容用 >>，或先 cp errors.txt errors.txt.bak 备份。
🧠 Explanation：> 在文件已存在时直接截断，无提示。重定向前先想清楚要不要保留旧文件。

06 Engineering Scenarios 工程场景

先写自己的方案，再展开看答案。每个场景想「三个月后的人能否看懂」。

场景 1：一个 5 GB 的 SRR12345678.fastq.gz，要数里面有几条 read，但不能解压、不能额外占 5 GB 空间。怎么一条命令搞定？

参考方案

zcat SRR12345678.fastq.gz | grep -c "^@"——流式边解边数，不落盘。或用 zcat ... | wc -l 得总行数再 ÷4。

场景 2：一个 sample.vcf 前 50 行全是 ## 注释和列头，你要统计真正的变异记录有多少条。

参考方案

grep -v "^#" sample.vcf | wc -l——-v 反选掉所有 # 开头的行，剩下的就是变异记录。

场景 3：一个基因表达表有几万行，你要找「出现次数最多的 top 10 基因」，命令要能被同事复用（改个数字就能要 top 20）。

参考方案

cut -f1 counts.tsv | sort | uniq -c | sort -nr | head -n 10——把末尾的 10 改成 20 即可。注释写清「N 在 head -n N」。

场景 4：排查日志时，你想把 ERROR 行存成 errors.txt 留档，同时马上知道一共有几行，不想跑两遍。

参考方案

grep "ERROR" align.log | tee errors.txt | wc -l——tee 一份写文件、一份继续走管道给 wc，跑一遍得到两样东西。

07 Boss Fight（15–20 分钟）

任务：对一个小型测序项目做一次「数据体检」，全程用管道完成，并修好一个被埋的坑。

要求（可度量交付物）：

  • 建 pipe_battle/，造 reads.fastq（4 条 read）、sample.vcf（含 ## 头 + 若干变异行）、genes.txt（若干基因，有重复）。
  • 用管道统计：read 数、变异记录数、每个基因出现次数、top 2 基因。
  • 用 tee 把「基因计数」存成 gene_counts.txt，同时打印到屏幕。
  • 全程 tmux 分屏（左屏跑管道、右屏 cat 原文核对），截图留证。
⚠️ 埋了一个坑

你统计基因计数时直接写了 cat genes.txt | uniq -c（忘了先 sort），结果同一个基因被拆成好几行、计数全错。你要自己发现「uniq 只去相邻重复」这个坑，改成 cat genes.txt | sort | uniq -c 修好，并截图「错误计数 → 修复后正确计数」。

验收清单：read 数 ✅ 变异数 ✅ 基因计数 ✅ top2 ✅ tee 留档 ✅ 埋坑（漏 sort）已修复 ✅ 截图 + 命令进 github/lesson09/ 并 git push ✅。
