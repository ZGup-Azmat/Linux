01 Mission Context 任务背景

昨天你用 find 锁定了「哪些文件」。今天主管要你钻进文件里面去捞信息：

  • 🔍 一个 50000 行的比对日志 align.log，找出所有含 error 的行。
  • 🧬 一个基因表达表 gene_expression.tsv，找出所有含 TP53（抑癌基因）的行。
  • 📊 一个 VCF 变异文件，统计某条染色体上有多少条记录。

find 管「找文件」，grep 管「找内容」——这是数据排查的黄金搭档。grep 全称 global regular expression print，即「全局正则表达式打印」。

Context → Need → Tool

要在大文件里搜特定文本 → 需要按模式匹配行 → 用 grep（-i / -n / -v / -r / -c / -E 正则）。

02 Knowledge 知识（≤25%，约 15–20 分钟）

3 concepts. Each: 英文定义 + 中文注释 + 心智模型 + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

Concept 1 · Basic matching: grep pattern file

English: grep prints every line of a file that contains a match for the pattern you give. Basic form: grep PATTERN FILE.

中文：grep 模式 文件 打印文件里「包含该模式」的每一行。

Syntax：

grep "error" align.log        # find lines containing "error"
grep TP53 gene_expression.tsv  # find lines containing TP53
grep -i "error" align.log      # -i: ignore case（忽略大小写）
grep -n "error" align.log      # -n: show line numbers（显示行号）
grep -v "error" align.log      # -v: invert, 打印不含的行

实例：grep -n "error" align.log 输出所有含 error 的行，并带上行号，方便你直接跳到日志出错的位置。

边界情况 / 常见失败
  • 默认区分大小写：grep "Error" 匹配不到 error（小写）。要忽略大小写加 -i。
  • 模式里有空格要引号：grep disk full log 会被当成「找 disk，再在 full、log 两个文件里找」，正确写法 grep "disk full" log。
  • grep 匹配的是「整行」：只要某一行里任何一个位置含模式，整行都会输出——所以可能输出一长串。
工程场景 / 为什么需要它

排查问题永远是「先 grep 出错行」。几万行的日志、几千行的基因表，grep 一秒定位到相关行，比人眼翻快几千倍，还不会漏。

衔接点

本概念是 Lesson 06（find）的另一半：find 找文件，grep 找内容。概念 2 展开 grep 的「批量」玩法。

Concept 2 · Recursive & counting: -r / -c / -l

English: grep can search whole directories (-r), count matches (-c), or list only matching filenames (-l) — turning it into a batch search tool.

中文：-r 递归搜整个目录、-c 统计匹配行数、-l 只列文件名，让 grep 变成批量检索工具。

Syntax：

grep -r "TP53" data/         # 递归搜 data/ 下所有文件
grep -c "error" align.log     # 统计 error 出现了几行
grep -l "TP53" *.tsv          # 只列出哪些文件含 TP53
grep -rn "error" logs/        # 递归 + 显示行号 + 文件名

实例：想知道「哪些样本表里有 TP53 这个基因」：grep -l "TP53" *.tsv 只输出文件名，一眼看清范围，不用看内容。

边界情况 / 常见失败
  • -c 统计的是「行数」不是「次数」：一行里 error 出现 3 次，-c 只算 1。要统计总次数用 grep -o "error" | wc -l。
  • grep -r 会进所有子目录：目录很大时慢，先想清楚搜哪里，别动不动 grep -r pattern /。
  • 二进制文件可能乱码：grep 搜到二进制文件会输出乱码，加 -a（当作文本）或 -I（跳过二进制）。
工程场景 / 为什么需要它

生信里「这个基因在哪些样本里表达」是最常见的需求。grep -l 列文件名、grep -c 数行数，让你从几千个文件里快速圈出范围。

衔接点

-r 让 grep 和 find 一样能「跨目录」。概念 3 讲正则表达式，让匹配从「固定字符串」升级到「模式」。

Concept 3 · Regular expressions: -E, anchors, character classes

English: A regular expression (regex) is a pattern that matches text flexibly: anchors (^ start, $ end), classes ([0-9]), quantifiers (*, +). Use -E for extended regex.

中文：正则表达式用「模式」灵活匹配文本：锚点 ^/$、字符类 [0-9]、量词 */+。加 -E 用扩展正则。

Syntax：

grep "^ERROR" align.log           # 以 ERROR 开头的行（^ 行首）
grep "\.bam$" files.txt           # 以 .bam 结尾（$ 行尾，\. 转义点号）
grep -E "chr[0-9]+" sample.vcf    # chr 后跟数字（-E 扩展正则）
grep -E "error|failed" align.log  # error 或 failed（| 或）
grep -E "^[0-9]{4}-[0-9]{2}-[0-9]{2}" log  # 日期开头的行

实例：从日志里只捞「ERROR」级别的行（排除 INFO 里含 error 单词的干扰）：grep -E "^ERROR" align.log 用 ^ 锚定行首，精确多了。

边界情况 / 常见失败
  • . 是任意字符不是「句号」：grep "chr1." 会匹配 chr1A、chr1x 等。想匹配真正的点号要 \. 转义。
  • * 是「零或多个」不是通配符：grep 正则里 * 作用在前一个字符上（如 ab* = a 后跟零或多个 b），和 shell 通配符不同。
  • | 和 + 需要 -E：不加 -E 时 | 会被当普通字符，要加 -E 才当「或」用。
进阶提示（可跳过）

完整正则还有 ?（零或一个）、{n,m}（n 到 m 次）、\b（词边界）等。生信最常用的是「锚定 + 字符类 + 或」，够排查 90% 的问题。

衔接点

正则是 grep / sed / awk / vim 共同的底层语言（Lesson 12 sed、Lesson 11 awk 都会用到）。这一课打地基。

05 Debug Challenge 排错挑战

5 个真实 Ubuntu Server 24.04 会遇到的报错。Problem → Think → Answer → Explanation。

调试 1 · grep "Error" 无输出，但文件里明明有 error
Problem：搜 "Error" 没结果。
💭 Think：大小写对得上吗？
Answer：grep 默认区分大小写，加 -i：grep -i "error"。
🧠 Explanation：Error（大写 E）和 error（全小写）是两个不同的模式。
调试 2 · grep disk full log 报错或结果不对
Problem：想搜「disk full」这个短语，结果不对。
💭 Think：空格被当成参数分隔了吗？
Answer：加引号：grep "disk full" log。
🧠 Explanation：不加引号，disk 是模式，full 和 log 被当成文件名。
调试 3 · grep "chr1." 匹配到 chr1A、chr1x 等
Problem：想找「chr1.」却匹配到 chr1A。
💭 Think：. 是普通点号还是通配？
Answer：转义：grep "chr1\."。
🧠 Explanation：正则里 . 是「任意单字符」，要匹配真正的点号用 \.。
调试 4 · grep -c "error" 统计结果比预期少
Problem：一行里有多个 error，-c 只算 1。
💭 Think：-c 数的是什么？
Answer：-c 数「匹配的行数」，要数「总次数」用 grep -o "error" | wc -l。
🧠 Explanation：-c 是 count lines，不是 count matches。
调试 5 · grep -E "error|failed" 不加 -E 时 | 没当「或」
Problem：不加 -E，| 没生效。
💭 Think：| 需要扩展正则吗？
Answer：加 -E：grep -E "error|failed"；或用基础语法 grep -e error -e failed。
🧠 Explanation：基础正则里 | 是普通字符，-E（扩展正则）才把它当「或」。

06 Engineering Scenarios 工程场景

先写自己的方案，再展开看答案。每个场景想「三个月后的人能否看懂」。

场景 1：一个 5 万行的比对日志，你只要「ERROR 级别」的行（排除 INFO 里提到 error 的干扰）。怎么写最精确？

参考方案

grep -E "^ERROR" align.log——用 ^ 锚定行首，只匹配以 ERROR 开头的行。

场景 2：一个基因表达目录有 500 个 .tsv，你想知道「TP53 在哪些样本里出现」，只想要文件名清单。

参考方案

grep -l "TP53" data/*.tsv——-l 只列文件名，不输出内容，一眼看清范围。

场景 3：你要统计每个日志文件里 error 的行数，做成一份「错误概览」交给同事。

参考方案

grep -c "error" *.log——每个文件名后跟一个数字，就是一份错误概览。

场景 4：VCF 文件里染色体字段是 chr1…chr22、chrX、chrY，你只要常染色体的记录（chr1–22）。

参考方案

grep -E "^chr[0-9]+" sample.vcf——^ 锚定行首 + [0-9]+ 匹配数字，chrX/chrY 被排除。
