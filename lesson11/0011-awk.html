01 Mission Context 任务背景

grep 能按行「找」，但不能按列「算」。今天主管要你对表格数据动真格：

  • 🧬 一个表达矩阵 counts.tsv，要找出表达量 > 100 的基因（按第二列数值过滤）。
  • 📊 要算出某列所有值的总和、平均值（比如样本总 read 数）。
  • 🧾 一个 VCF/日志，只要某几列（抽出 chr 和 pos）。
  • 🔢 要给输出加表头、加行号、重新排列列的顺序。

awk 就是干这个的——按「模式 + 动作」逐行扫描，把每行按分隔符拆成字段，然后你就能对每一列做过滤、计算、格式化。

Context → Need → Tool

要按列过滤/计算/重排 → 需要一个逐行按字段处理的工具 → awk（模式-动作、$1/$2 字段、-F 分隔符、NR/NF、BEGIN/END）。

02 Knowledge 知识（≤25%，约 15–20 分钟）

3 concepts. Each: 英文定义 + 中文注释 + 心智模型 + 语法 + 实例 + 边界情况 + 工程场景 + 衔接点。

Concept 1 · Pattern–action model + fields $1/$2 + -F

English: awk reads line by line, splits each line into fields ($1, $2, …) by a delimiter (-F, default whitespace), and runs pattern { action } on every line. $0 is the whole line.

中文：awk 逐行读入，按分隔符（-F，默认空白）把每行拆成字段 $1/$2/…，然后对每行执行「模式 { 动作 }」。$0 是整行。

Syntax：

awk '{print $1}' file              # 打印第一列
awk '{print $1, $3}' file           # 打印第 1、3 列（逗号=空格连接）
awk -F '\t' '{print $2}' counts.tsv # 用 Tab 分隔，取第 2 列
awk -F ':' '{print $1}' /etc/passwd # 用冒号分隔
awk '{print $0}' file               # 打印整行（$0）

实例：awk '{print $1, $2}' counts.tsv 把基因表达表的每行只保留「基因名 + 表达量」两列，其余列全部丢弃——grep 做不到的「按列裁剪」，awk 一条搞定。

边界情况 / 常见失败
  • 默认分隔符是「连续空白」：空格、Tab 都被当作分隔；但 Tab 分隔的 TSV 里若有空字段，用默认空白会「吃掉」空列。列是 Tab 分隔时，务必显式 -F '\t'。
  • $1 和 shell 的 $1 会撞车：awk 程序必须用单引号包起来，否则 shell 会先把 $1 换成自己的参数。记：awk 脚本永远单引号。
  • print $1, $2 的逗号是空格：想贴在一起用 print $1$2（无逗号）；想自定义分隔用 print $1 ":" $2。
  • -F 是分隔符不是字段：-F '\t' 里的 \t 在单引号里才会被 awk 识别为 Tab。
工程场景 / 为什么需要它

生信表格（TSV/BED/GFF/VCF）都是「列对齐」的数据。awk 的字段切分让你能精确抽列、按列过滤，是处理这些格式的基本功。

衔接点

grep 是「找行」，awk 是「拆列」。概念 2 讲 awk 的内建变量，让行处理更有上下文。

Concept 2 · Built-in variables: NR / NF / $0 / FS / OFS

English: awk tracks state in built-in variables: NR (record/line number so far), NF (number of fields in current line), $0 (whole line), FS (input field separator), OFS (output field separator).

中文：awk 用内建变量记录状态：NR（当前行号）、NF（当前行字段数）、$0（整行）、FS（输入分隔符）、OFS（输出分隔符）。

Syntax：

awk '{print NR, $0}' file           # 加行号（NR + 整行）
awk '{print NF}' file                # 每行有几个字段
awk '{print $NF}' file               # 打印最后一列（不管有几列）
awk -v OFS='\t' '{print $1, $2}' file # 输出用 Tab 分隔
awk 'BEGIN{FS=","} {print $1}' file  # 在程序里设输入分隔为逗号

实例：awk '{print NR, $0}' counts.tsv 给每行加行号——写报告时标注「第 N 行是哪个基因」很方便。awk '{print $NF}' 则不管列数，直接抓最后一列。

边界情况 / 常见失败
  • $NF 是最后一列，不是「最后字段号」：$NF 取的是值，NF 才是数字。别混。
  • -v OFS 要在程序前：awk -v OFS='\t' '{...}' 顺序不能反。
  • NR 对多文件是连续累计的：awk '{print NR}' a.txt b.txt 会从头数到尾不重置，跨文件行号会接着涨。
  • print 默认 OFS 是空格：逗号连接的字段之间默认是空格，想要 Tab 用 -v OFS='\t'。
工程场景 / 为什么需要它

加行号（NR）、抓最后一列（$NF）、重设输出分隔（OFS），这三个是写报告和转格式的高频动作，比手动数列可靠得多。

衔接点

有了字段和变量，概念 3 加「条件」和「BEGIN/END」就能做真正的计算了。

Concept 3 · Condition filtering + BEGIN/END + arithmetic

English: A pattern before {} filters lines (e.g. $2 > 100). BEGIN {…} runs once before reading input, END {…} once after — used for headers, totals, averages.

中文：{} 前的「模式」用来过滤行（如 $2 > 100）。BEGIN{…} 在读输入前执行一次、END{…} 在读完后执行一次——用于加表头、算总和、算平均。

Syntax：

awk '$2 > 100 {print $1, $2}' counts.tsv          # 过滤第二列 > 100
awk '$2 > 100 && $3 == "up" {print}' expr.tsv   # 两个条件同时满足
awk '{sum += $2} END {print sum}' counts.tsv        # 第二列求和
awk '{sum += $2; n++} END {print sum/n}' counts.tsv  # 第二列求平均
awk 'BEGIN {print "gene\tcount"} {print $1 "\t" $2}' counts.tsv  # 加表头
awk '$3 == "chr1" {print $1, $2}' sample.vcf        # 按第三列（chr）过滤

实例：「表达量 > 100 的基因」：awk '$2 > 100 {print $1, $2}' counts.tsv 只输出第二列数值大于 100 的行。「样本总 read 数」：awk '{sum += $2} END {print sum}' counts.tsv 把第二列全加起来。

边界情况 / 常见失败
  • 数值比较要确保字段是数字：如果字段是 NA 或带单位（如 100bp），$2 > 100 会按字符串或按 0 处理，结果诡异。
  • 字符串比较用 == 和引号：$3 == "chr1" 要带引号；$3 = chr1 是赋值不是比较。
  • += 未初始化时默认 0：sum += $2 第一次 sum 是空，awk 自动当 0，好用；但 END {print sum/n} 若 n 为 0 会除零。
  • 模式里的 > 在 shell 单引号内才安全：单引号保护下 awk 才拿到 >，否则被 shell 当重定向。
进阶提示（可跳过）

awk 还支持 if/else、数组、printf 格式化、内置函数（length/substr/tolower）。日常生信 90% 用「模式过滤 + BEGIN/END 求和」就够，剩下的用到再查。

衔接点

awk 是「列处理」的终点，Lesson 12 的 sed 补上「行内替换/删除」。两者合起来覆盖绝大多数文本整形需求。

05 Debug Challenge 排错挑战

5 个真实 Ubuntu Server 24.04 会遇到的报错。Problem → Think → Answer → Explanation。

调试 1 · awk {print $1} file 报错或结果不对
Problem：没加单引号，awk 程序被 shell 拆开。
💭 Think：{} 和 $1 会被 shell 抢吗？
Answer：awk 程序必须单引号：awk '{print $1}' file。
🧠 Explanation：不加引号，shell 会把 $1 换成自己的参数、把 {} 当特殊字符，awk 拿到的是残缺程序。
调试 2 · awk '$2 > 100' counts.tsv 结果里混进 NA / 带单位的行
Problem：数值比较把非数字也放行了。
💭 Think：字段真的是数字吗？
Answer：awk 对 NA 等非数字按字符串或 0 比较，结果诡异。先确认字段干净，或加 $2+0 == $2 判断是数字。
🧠 Explanation：数值比较的前提是字段可解析为数字，脏数据会破坏过滤。
调试 3 · awk '$3 = "chr1"' sample.vcf 打印了所有行
Problem：想过滤 chr1，结果全输出了。
💭 Think：用了 = 还是 ==？
Answer：= 是赋值，== 才是比较。改成 awk '$3 == "chr1"' sample.vcf。
🧠 Explanation：$3 = "chr1" 给 $3 赋了值且恒为真，所以每行都打印。
调试 4 · awk '{print $1, $2}' 输出的两列之间是空格，但你想要 Tab
Problem：print 用逗号，输出分隔是空格。
💭 Think：怎么改输出分隔符？
Answer：用 -v OFS='\t'，或显式 print $1 "\t" $2。
🧠 Explanation：print 里逗号连接的字段默认用 OFS（空格）分开，改 OFS 或手工插分隔符。
调试 5 · awk '{print NR}' a.txt b.txt 的行号跨文件一直涨
Problem：第二个文件的行号不是从 1 开始。
💭 Think：NR 会跨文件重置吗？
Answer：NR 是全局累计，跨文件不重置。想每个文件单独数用 FNR（每个文件的当前行号）。
🧠 Explanation：NR 是「到目前为止读过的总行数」，FNR 才是「当前文件的行号」。

06 Engineering Scenarios 工程场景

先写自己的方案，再展开看答案。每个场景想「三个月后的人能否看懂」。

场景 1：一个表达矩阵（基因、count、状态三列），要找出「count > 100 且状态为 up」的基因名。

参考方案

awk '$2 > 100 && $3 == "up" {print $1}' counts.tsv——模式里用 && 组合数值和字符串条件。

场景 2：一个样本有几千行 read 计数，要算「总 read 数」和「平均 read 数」写进报告。

参考方案

求和 awk '{s+=$2} END {print s}'；平均 awk '{s+=$2; n++} END {print s/n}'。用 BEGIN 打印标签、END 打印结果。

场景 3：一个 VCF 表有很多列，你只要 chr 和 pos 两列，并加表头 chr\tpos。

参考方案

awk 'BEGIN {print "chr\tpos"} {print $1 "\t" $2}' sample.vcf——BEGIN 加表头，body 抽两列。

场景 4：你拿到一个每行列数不固定的表，要抓「最后一列」（可能是 status、可能是别的）。

参考方案

awk '{print $NF}' file——$NF 永远指向最后一列，不用管有几列。

⚠️ 埋了一个坑
